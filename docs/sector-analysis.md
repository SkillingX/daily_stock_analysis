# 个股板块分析（板块专项）

个股板块分析是独立专项入口（Web 菜单「个股板块分析」，API 前缀 `/api/v1/sector-analysis`）：
输入一只 A 股，生成以**同一东财行业板块**为研究主体的基础报告，可在桌面端与移动端回看历史、
打开详情、下载 Markdown 存档。本专项与「个股深度投研」相互独立：不改深研的维度、权重、
模型、默认范围、取消与缓存身份，也不共享其供应商身份规则。

本文档覆盖 issue #81 交付的基础报告闭环、issue #82 交付的近期板块趋势/同业比较，
以及 issue #83 交付的行业催化（统一准入）与证据化综合研判。

## 报告内容与口径

新报告（载荷版本 2）不产出综合评分与分档结论（无总分、无「中性/顺风」分档、无行动建议）。
报告组织为（与正文章节一致）：

1. **主行业定位（同一东财行业板块）**：东财个股行业名 → 东财行业板块全表**精确名称+板块代码**
   双确认锁定（如 白酒Ⅱ = BK1277）→ 同板块成分表验证目标股归属。申万一/二/三级链仅作
   **归属参考单列**（已做 Ⅱ/Ⅲ 级后缀命名归一），不与东财成分/行情混算。
2. **当日板块行情（价格强弱与活跃度）**：涨跌幅/全表排名、换手活跃度、成交额活跃度、
   广度（上涨家数占比）。**这是当日行情，不代表产业景气；「成交额活跃度」是成交额相对
   水平，不是资金净流入**；单日行情不构成趋势结论。涨跌幅资格与名次口径（issue #81
   第三、四轮）：pandas NaN/±inf 等非有限数视为缺失；目标涨跌幅缺失时不计算动量/排名
   （不伪造分位）；**同行涨跌幅存在缺失/非有限时有效样本 ≠ 观测全表，不输出无依据的
   全表名次**——`rank_of=null`，缺口注明有效样本数/观测总量及原因；动量仍按有效样本
   计算（`严格低于目标的有效样本数 ÷ (有效样本数−1) × 100`，并列值不计入
   「低于」数——并列最高不恒为 100 分、全相等为 0 分），正文口径说明
   与该公式一致，不使用「前 10%=100 分」「最低=0 分、最高=100 分」类不成立表述；
   有效样本不足 2 个（含观测表仅 1 行、仅目标 1 个有效或全表无有效涨跌幅）时
   比较样本不足，动量与全表排名保守 N/A，缺口注明有效样本数/观测总量及原因；
   全表涨跌幅全部有效时名次 =
   严格高于目标的个数 + 1（最高=1，并列最高同为 1，不用 total-below 把并列排末）；
   `total_boards` 保持观测板块总量（含缺失/非有限行）。同行缺失只是排名/样本资格缺口，
   其他有效事实保留，不机械降级整份报告。
3. **近期板块趋势（最近 20 个已完成交易日，issue #82）**：详见下文「近期板块趋势」节。
4. **行业催化（近期政策/新闻，统一准入，issue #83）**：详见下文「行业催化」节。
5. **同业比较（成交活跃代表，issue #82）**：详见下文「同业比较」节。
6. **证据化综合研判与风险（issue #83）**：详见下文「证据化综合研判」节。
7. **政策倾向（行业 DNA 库·静态规则背景）**：本地规则库的关键词匹配方向（支持/中性/限制），
   反映产业目录与政策文件的总体取向，不是近期新闻事件。
8. **行业基率（启发式先验背景，非实测胜率）**：本地启发式默认表，报告透出版本与更新日期；
   命中失败时使用默认值 0.5 并明确标注，**不据默认先验产生任何「中性」判断**。
9. **相关概念（仅列示）**：iFinD 概念入口有界读取；入口未启用或供应商失败记入缺口，
   不影响主报告；概念不作为行业归属依据，不展开独立研究。

### 行业催化（issue #83）

- **统一准入路径**：每条候选经过同一序列——**候选文本类型契约**（单一入口、两个
  日期分支共享：title/url 必须是非空字符串，可选 snippet 出现即必须是字符串；
  缺失/类型非法/空白为畸形行，按 `dropped_invalid_field` 本地拒绝计数——不
  `str(...)` 把 dict/字节/数字伪合法成标题/摘要（真实供应商 JSON 的 `title=dict`
  曾被字符串化为假标题），剩余有效行与事实全部保留，缺失可选文本只是缺字段、
  不产生 500。**MiniMax raw 行在同一契约下于共享适配器入口先行校验**（root 批准的
  最小共享改动）：organic 行在切片/域名/日期处理前校验实际类型（title/link 必需
  非空字符串，snippet/date 可选——缺失合法、出现必须字符串），畸形行逐行拒绝并按
  `SearchResponse.malformed_rows` 结构化计数（既有复制/过滤/限行路径保留该字段），
  有效行全部保留——raw rows=[有效, snippet 对象, 有效] 不再因切片 TypeError 整批
  变空失败；全部畸形是显式数据失败（不冒充「无新闻」），真正空 organic 是合法空；
  板块准入把供应商畸形行计数**并入** `dropped_invalid_field`（供应商侧与本地准入
  拒绝作用对象不相交，无双重计数；含 fallback 尝试中已见的畸形行））→ 来源验证
  （**公共 HTTP(S) URL 结构契约**：scheme 必须是 http/https、urlsplit 可解析、
  hostname 合法、无 userinfo、显式端口 1-65535、literal IP 必须 global 且非
  multicast（IPv6 literal 按解析后的完整地址判定）、localhost/.local 名义主机拒绝、
  **hostname 完整保留为来源身份**（DNS 全名上限 253；超限本地拒绝
  `source_host_too_long`——绝不截断后当同源判定身份，两个合法长域名共享前缀
  不会伪同域合并）、字段类型非法或 URL 超长按本地供应商数据错误计数——不截断伪造）
  → 行业相关性（行业名或基词命中标题/摘要；标题含目标股名+个股活动词（运动会/年会等）
  不冒充行业催化）→ 日期获得 → **同一个**事件资格/去重登记。供应商带日期与文章探查
  补日期两条分支只在「日期获得」一步不同，事件资格完全共享——背景条目不存在绕过事件
  资格的升级捷径。**溯源域名一律取实际文章 URL 的完整解析 hostname**
  （`urlsplit.hostname`：域名去端口小写、IPv6 literal 取 brackets 内完整地址——
  永不按冒号切分 netloc，也永不截断）；供应商 source 标签不是域名替身（类型非法
  忽略即可，不影响准入、不 500）。
- **日期获得两分支**：供应商发布字段走共享 `SearchService._normalize_news_publish_date`
  归一化；无日期候选做**有界文章探查**（≤3 条、同一取数预算、requests `stream=True`
  有界读取）。文章日期证据合同：URL 中的日期不单独作证据（URL-only 保持背景）；文章
  声明日期只接受可识别的 HTML 出版元数据（`article:published_time` 等标准 meta），
  保存实际 meta 标签作为原始依据（`date_basis_detail`）；**实际文章（终态 URL）的
  声明日期**与元数据日期冲突（provenance 冲突）保守拒绝——重定向后的终态地址是
  实际文章地址，其 URL 日期参与同一冲突判定（original.html→302→/2020/…→200 meta
  2026 = URL/meta 冲突，不因原始 URL 无日期而绕过）；**一致日期的重定向照常合格**
  （终态 URL 声明与元数据一致即两源互证）；直接请求同一终态 URL 与经重定向到达
  资格判定完全一致。**终态已知即保留 provenance**：探查到达实际终态后（成功或
  已到达终态的安全失败——非 2xx/读取超限/超时/解析失败），条目保留原引用 `url`
  + `final_url`（实际文章地址）+ `source_domain`（终态完整 host）——已证实催化与
  **背景条目一致**（日期冲突/历史回顾/同文重复 alias/到达终态的安全失败背景同样
  不丢实际文章溯源，`background_items[].final_url` 追加默认 None 字段，provider
  口径与终态未到达的失败为 None）；去重登记键随展示 provenance 一致重键到实际文章
  （先按原键摘除再按终态键重注册，不先改域名后摘键）；终态未到达的失败（传输/
  redirect 边界/出站前拒绝）不猜终态。无法确证 → 保持背景 + 如实降级说明。
  探查耗尽取数预算时**局部终止探查**（已取得催化/背景保留，缺口注明）——文章探查
  超时是部分报告，不传播整报 504。
- **文章探查同一有界 I/O 契约**：单响应字节上限（`CATALYST_ARTICLE_MAX_BYTES`，
  1MB）在**读取期间强制**（stream 逐块累计，超限立即停止并关闭响应——已装 newspaper
  0.2.8 `Article.download` 是非 stream 全量读，探查只需出版元数据不走它）；解析只在
  有界内容上复用已装 `Parser.fromstring` + `get_publishing_date`（不全文提取）；
  redirects 手动逐跳（`allow_redirects=False`）**先校验后连接**——每一跳 Location 在
  出站前过同一边界契约，重定向不实际连出公共 HTTP(S) 边界（自动跟随会让 requests
  先连到目标再检查，逃逸已经发生），跳数有界防循环。**最终响应成功性先于读取/解析**：
  重定向终态到达后先校验状态码，非 2xx（403/404/500/304 等）是本地文章来源失败
  （`article_http_error:<status>`）——关闭响应、零日期升级、错误 body 不进 parser、
  零 body/header/查询串泄漏；来源失败 ≠「窗口内无新闻」（背景条目保留安全原因）。
  **错误显式分类**：已识别传输（requests RequestException）/读取超限（article_oversize）/
  HTTP 错误状态（article_http_error）/解析数据失败（newspaper `fromstring` 显式 None
  契约 → `ArticleParseFailure`）降背景 + 安全原因；TypeError/AssertionError 等程序/
  契约错误原样传播（诚实失败，不伪装成「无日期」）。绝对 requests 预算出站前显式幂等
  安装 `eastmoney_patch(budget_only=True)`——ContextVar 只有 patch 在位才真正钳制
  requests 出站（fresh process 中 Tenacity 重试同样受 fetch_deadline 钳制，deadline
  后零 wire；维护测试经真实公共 POST 入口验证首请求 timeout ≤ wire 时刻剩余预算）。
- **事件资格（两个日期路径一致）**：发布日期在窗口内（不含未来日）才算催化候选——
  发布日期只作窗口资格依据，**事件日期未知即为未知，不用发布日期顶替**；历史回顾降级
  按**标题主题时点**口径且**保留声明精度**（不发明缺失精度）：标题声明的完整有效日期
  与实际窗口起始逐日比较（声明 11-01、窗口 11-04 起 → 回顾；窗口内/同日声明不降级），
  年月声明与实际窗口月比较（整月早于窗口才降级，同月声明不降级），仅年声明与实际窗口
  年比较；取各声明的保守上界最晚者为主题时点。无效日期分量（13 月/2 月 30 日）本地按
  低一级精度保守处理，不产生错误。正文引用旧年份不触发——新政策正文提到历史比较不降级。
  **无标题豁免词表**：「对比/修订/新版/废止/取代/vs」等词不再绕过日期主体判定——
  今天发布的「白酒行业2020年与2019年销量对比」是历史背景，不是已证实近期催化；
  标题声明最晚年月为当前（如「2026年新政 与2018年版对比」）不降级。歧义时保守降级
  为明确受限背景，不发明当前事件。
- **去重与同源转载**：URL 归一化去重（剥跟踪参数/fragment），去重键按**实际文章**
  （article 口径用终态地址——同一篇文章的两个重定向 alias 不算独立确认，先到者
  保留、后到者按重复计数；背景条目在终态已知后同样重键到实际文章身份，后续同文
  alias 对它按重复计数）；同域同题判重（域名取实际文章完整 host）；跨域同题
  + 明确转载标记（「来源：」「转自」「转载」等）→ **同一事件**合并（保留原始来源归属
  与补充链接 `same_event_urls`，不产生第二个独立 ID）——域名数量不冒充独立确认。
  无语义聚类服务，保守显式规则。
- **供应商失败 ≠ 无新闻**：显式失败响应（如 HTTP 403）保留 sanitized 供应商名与错误
  类别（复用 `run_diagnostics.sanitize_diagnostic_text`，headers/keys/secrets 先脱敏
  再截断），缺口文本与「窗口内真实无新闻」分开；合成 Authorization/Bearer 等凭据
  不进入载荷/Markdown/日志；供应商 raw 行全部畸形是**显式数据失败**（结构化计数随
  响应携带、错误类别如实保留），真正空结果才是合法「无新闻」。
- **背景线索（bg-\*）**：无日期或降级条目最多列示 3 条，明确限制标记——不参与已证实
  催化、不作为模型重要结论的唯一事实依据；探查已到达实际终态的背景保留
  `final_url` 与实际文章域名（生成/详情/下载/模型登记材料同源读回）。过滤计数
  （重复/转载/窗口外/无关/无效来源/无效字段——含供应商侧 raw 畸形行）逐类透出。
- **可见引用（渲染契约）**：已证实催化与背景条目的**标题一律链接至原始引用 URL**
  （`[标题](url)` 普通 Markdown 链接，两条日期路径一致），催化表保留完整来源域名
  列、背景表同样显示实际 `source_domain`；终态 URL ≠ 原引用时既有终态地址行
  照常保留（原始引用与实际终态同时可见）。生成响应、存档、详情与下载四入口
  逐字一致——下载的报告可直接溯源到每条采用资料。标题投影到 GFM 表格时在
  渲染层做字面转义（`\` 先行转义、`|`/`[`/`]` 字面化、换行折叠为空格，
  `md_link_text` filter）：真实标题含字面 `|`（如「去库存| 财经日日评」）时
  保持标题原文可见、永不成为列定界符，日期/口径/来源各归其位；反斜杠先行
  转义保证标题已有 `\` 时插入的转义序列不重组出新定界符（`政策\]解读` 不因
  反斜杠加倍丢 anchor），方括号 literalize 保证完整标题留在单一原始 href
  anchor 内（`政策\[解读| 资讯` 前缀不脱落链接外）；载荷与存档 JSON 中
  标题原文不转义、逐字不动。

### 证据化综合研判（issue #83）

- **资格与状态机**：主行业 `confirmed` 且**存在已证实近期催化**才调用模型
  （`no_qualified_facts`——静态先验/背景不产生空泛完整叙事）；模型未配置
  （`model_unavailable`）/调用失败或超时（`model_error`）/输出未通过校验
  （`malformed_output`）是不同状态，合格事实保留、缺口如实，不用默认基率或空泛
  模型文字补完整叙事。综合缺失/失败使报告完整性 partial（原因累积可见）。
- **证据登记表**：服务端按 evidence ID 注册**实际取得**的合格事实
  （identity/intraday/trend/peers/target/cat-N/bg-N）——缺失的块根本不注册，
  模型无法引用它们补造；静态政策 DNA 与基率先验**不注册**（仅报告背景，不能独立
  支撑结论）；身份事实不含行情数值（身份不能佐证 fabricated metrics）；bg-\* 只能
  附加引用、不得唯一支撑。语义标题与口径元数据保留在登记表材料中
  （momentum 是有界横截面涨跌幅分位、peers 携带权威 `selection_rule`）。
- **摘要与观察限制的所有权（root-decision）**：新生成报告的
  `summary`/`uncertainty_note` 由**服务端从已采纳事实程序化生成**
  （`summary_origin="server_facts"`）——精确带符号百分比/排名/样本/窗口与
  单期限制直接从已有值渲染（`program_fact_summary`/`program_fact_limitations`，
  每个关系单一 owner、无阈值/形容词序数/新金融计算），**不消费任何模型
  claims 文本**——模型错误句不可能进入两个核心字段。旧记录为历史
  validated-claim 拼接（默认 `legacy_model_claims`），原样读回不改写，
  渲染按 origin 诚实区分标注。
- **模型投影的市场字段排除**：非市场事实（identity/catalyst）原样投影
  （title/snippet/date/provenance/身份不变）；市场类证据
  （intraday/trend/peers/target）的 raw magnitudes（分位/排名/价格/收益）
  **不进入模型输入**，由 `market_observation_relations` 以确定性定性观察
  关系替代（当日涨跌符号、已存板块对基准相对关系、样本选取含义、单期
  范围）——原始值逐字保留在公开载荷/存档与报告服务端表格；观察关系含
  equal（持平）与缺失省略语义。
- **模型角色边界**：请求**一条**简洁的整合段落结论（同段覆盖主要催化剂
  含义、目标相关性与材料性反面证据/条件风险；市场概览与观察限制由服务端
  事实摘要承载，模型不复述），kind 按主导内容从现有枚举选择、材料性冲突
  以实际 refs 保留在段内、不因篇幅省略重大冲突、无证据的反面陈述不编造
  （公开 1..6 契约与每条全量校验不变——provider 超出请求返回的额外 claims
  逐条照常校验、不截断、rejected_count 照常计入 partial）；不对数值水平/
  顺序/持续做重新解读、不发明龙头/资金流分类。自由 prose 仍可能出错：
  claims 单独立示（模型 origin 可见），现有校验仅覆盖结构/引用/纯定性
  边界，语义准确性不由此保证——请以表格与所引原始材料为准；发布级人工
  语义验收是有限的开发验收环节（pending 状态如实），不是逐报告的运行时
  步骤——程序化核心字段是确定性边界，模型 claims 不由此获得正确性保证。
- **strict 校验与状态机不变**：qualitative/knownrefs/结构/行动词/超长全量
  前置校验、rejected→partial、绝对预算、单次调用生命周期照旧；factual
  summary 不能冒充成功的模型综合或把 partial 变 complete（综合缺失/失败
  状态照旧无 summary）。
- **综合指令的口径语义规则**：system 约束要求模型解读严格按材料口径标注——
  分位正值不表示收益为正或趋势延续、单期快照不外推为历史趋势、行情/涨跌幅/
  换手表现不是资金流入流出或投资者偏好的证据、同业按其标注选取规则理解不得
  升格为未经支持的公司分类（如龙头）；结论只依托材料实际支持的内容，不支持
  的地位/流向类因果或分类解释省略或明确标注为推测，并保留真实风险与反面证据。
- **模型输出纯定性（qualitative 契约）**：每条 claim 必须引用登记表内实际 ID
  （≤8 个；第 9 个未知引用即整条拒绝）；**陈述文本不得含任何数量字符或明确倍数词**——
  保守边界按 Unicode 数字属性（`str.isnumeric`：半角/全角数字、中文〇一二三十百千万
  亿壹贰、阿拉伯-印度数字、罗马数字、上标/分数等）加 Unicode 未覆盖的普通中文数量字
  简繁变体（两/兩、半、几/幾、俩/倆）逐字符判定，加**有限已知倍数词**（翻倍/翻番——
  不含数量字符的词级倍数表述，如「企业利润将翻倍」是显式利润 ×2 声明，材料没有
  利润数字时同样拒绝；仅此两个词级形态，不是不断增长的词表/单位本体，也不是通用
  NLP 语义验证器），**不依赖后随单位**（「目标股股价为一百元」「市盈率为十/两百」
  「١٢倍」「股价为倆元」等 unit-free 形态同样整条拒绝），违规陈述整条拒绝并记
  sanitized 原因（`quantitative_statement:<命中字符/词>`），全部数字事实保留。
  数字/日期事实由服务端从**所引条目**材料渲染到既有数字表格——模型不重述数值
  （wrong-owner 1.65% vs target 1.0、member_count 被借为 PE、target 1.0 被借为
  PE 1.0 等跨字段/跨主体/跨量纲借用从根上没有存活通道，也不存在数值 token 匹配
  语义接地的伪承诺）。**已知保守代价**（prompt 明示 + 本文档披露）：含数量字符的
  普通词与名称（一致/统一/一方面、三一重工、boardⅡ 等）一并拒绝——prompt 要求
  改用同义定性说法（相同/趋同/部分），不设短语白名单（会重新打开价格/数值通道）；
  prompt 与该契约同向对齐：system 约束要求陈述文本一律用中性指称（该板块/目标股/
  同业），不重印输入材料中的行业分类后缀、板块/股票代码、纯数字名称或带日期编号的
  标题/季度 label（指向走 evidence_refs），输出前在同一调用内逐条自检 text 字段、
  把量词句改写为有证据支持的等价定性表述（无等价支持则省略，不发明替代、不删真实
  风险/反面证据）；为降低含数量字符的身份标签被复述进陈述文本的风险，
  final user prompt 不再重复行业/股票标签；identity 证据 JSON 保持原样
  （不清洗输入、不改板块 label），prompt 对齐的合成 wire 回归证明输入身份
  与引用校验链路逐字保持，实际模型效果由真实报告验收观察；
  本契约是字符边界加有限倍数词合同，不是通用自然语言语义验证器，不声称语义级
  事实核查。证据 ID 是独立 refs 字段，不写进陈述文本；行动词（买入/卖出/目标价等）
  整条拒绝；超长/畸形/原始条数超限整体拒绝（全量前置校验，不清洗伪合法）。
  自然定性解读 + 反证/风险的证据关联结论照常通过——模型保留有用分析，不是罐头段落。
- **混合输出如实 partial（不呈现伪完整研究）**：status=ok 且存在被整条拒绝的结论时
  （`rejected_count > 0`，schema 追加字段、默认 0、旧载荷读取兼容），合格结论与全部
  服务端事实保留，但报告完整性 = partial 并附显式 rejected-output 原因（计数来自
  字段，不解析缺口文本）；Markdown 综合节显式显示拒绝计数与「完整性为部分」。
  正常全合格输出（rejected_count=0）保持 complete，全部被拒保持 malformed_output/
  partial——完整性口径与用户可见状态一致。
- **summary/uncertainty 由服务端程序化生成（root-decision 所有权）**：新生成
  报告的摘要与观察限制从已采纳事实渲染（`server_facts` origin），不消费模型
  claims 文本——模型错误句没有进入核心字段的通道；旧记录为历史
  validated-claim 拼接（legacy origin）原样读回。
- **绝对预算到真实 wire**：模型出站线程内绑定既有 `ResearchRun`/`request_deadline`
  生命周期（deadline = 报告取数截止，同一 monotonic 时刻域），队列等待、fallback
  循环、流式传输与每次 HTTP 重试共用同一绝对截止——不在路由选择后重置相对时钟；
  sector 搜索/文章/模型出站前显式幂等安装 `eastmoney_patch(budget_only=True)`
  （不启用 auth、不改共享默认）——ContextVar 只有 patch 在位才真正钳制真实
  requests/Tenacity 传输（fresh 进程验证：首请求 timeout ≤ remaining，
  fetch_deadline 后绝对零 wire，无上下文的下一个请求保持默认行为）；
  AkShare 统一工作线程（`_ak_with_retry`）在**真正执行 SDK 的线程内**同样
  幂等安装并绑定同一 fetch_deadline——SDK 内部分页/重试（如行业全表
  `fetch_paginated_data`）在调用方放弃后发出的新请求同样服从截止
  （截止后派发被拒绝，不产生新 wire）；线程上下文 finally reset（不向共享
  池下一个请求泄漏）；迟到 worker 只写自己的
  诊断，不 mutate 已返回报告或迟到归档。
- **程序错误不伪装（真实 SDK 包装下同样成立）**：共享 `LLMToolAdapter.call_text/
  call_completion` 可选 `propagate_program_errors`（默认 False，全部既有消费者
  行为不变）；板块综合以 True 调用。真实 SDK（LiteLLM）会把 httpx 终端程序错误
  包装成 InternalServerError 等远端异常（实测链：InternalServerError → __context__
  OpenAIError → __context__ APIConnectionError → __cause__ TypeError）——opt-in
  时对**真实异常对象链**（`__cause__`/`__context__`/SDK 保留的 `original_exception`
  属性）做有界环安全遍历，找到真实 TypeError/AssertionError 对象即 re-raise 原对象
  （API 层 500 程序错误、零存档），只查对象不匹配错误文本/类名子串：远端 HTTP500/
  JSON 消息提到「TypeError」但链上无真实对象时不误判，仍按 model_error partial 降块
  存档（fallback 语义不变）。已识别传输/超时/限流错误照常降块。

### 近期板块趋势（issue #82）

- **资格**：只有主行业身份 `confirmed`（板块名称+代码锁定且成分验证含目标股）才发起
  板块/基准日线查询并给趋势结论；`unverified`/`ambiguous`/`missing` 保留 #81 有效事实，
  趋势/同业块如实标注「未执行」，不发无资格出站（板块代码虽已锁定但归属未确认时同样不查询）。
- **窗口**：严格交易日历 `recent_completed_trading_sessions("cn", 20)` 取最近 20 个**已完成**
  交易日（盘中未收盘当日自动剔除、盘后含当日、节假日按交易日历而非自然日补齐）。
  交易日历不可用时记明确缺口且**不出站**（不按自然日 fallback）。
- **数据源**：板块日线走东财行业板块历史行情（**板块代码直查**，避免内部按名称再映射；
  `period=日k`、不复权）；基准为沪深300 指数日线（东财指数接口，与板块完全相同的期望窗口）。
- **合格性**（两源各自独立判定）：每个期望交易日恰一行且收盘为有限正数（日期必须可解析、
  在期望窗口内、无重复）。缺天（含收盘 NaN/±inf/0/负导致的天）如实注明具体日期与数量，
  **不取交集凑 20、不用窗口外旧日凑数**；窗口内重复日期冲突整源不合格（不静默取其一）；
  供应商乱序返回按日期对齐，不影响合格性；供应商日线返回错误形状（如 dict）或日期/收盘
  列畸形（如重复列名）、日期列整体不可解析，均按**源错误**降对应块记缺口，不逃出边界
  误报为用户请求错误。重复日期冲突、收盘无效、真缺失三类源缺陷**独立披露**（各自注明
  具体日期与数量，重复日不掩盖其他缺口），缺口文案有界（不因复合源失败炸最终校验）。
- **实际日线观测进载荷与正文**：`observations`（`{date, close}` 升序）与 `qualified_sessions`
  是板块/基准各自**实际合格观测**——合格时 20 条；部分合格时保留已取得部分与实际覆盖数
  （N/20，无发明值），缺口注明缺失/无效日期。观测展示与区间收益资格共用同一份判定结果，
  不重复判定逻辑。窗口内重复日期冲突时冲突日不展示（两个值都不取其一）、其余无冲突日期
  的合格观测保留。正文以表格展示（板块收盘为板块指数点位、基准为指数点位，供应商口径
  原样），生成/详情/下载读同一存档一致。
- **基准独立渲染**：基准覆盖数与基准观测表独立于基准收益、也独立于板块侧展示——板块
  残缺时合格基准的区间收益与观测仍在正文可见；基准部分合格（如 19/20，收益不可算）时
  基准实际观测与覆盖数同样进正文并说明相对表现不计算；相对表现不可算时正文说明需双侧
  同窗口均 20/20 合格。
- **收益语义**：20 个收盘形成 **19 个间隔**；区间收益 = 窗口首尾收盘复合
  （起止日由 `start_date`/`end_date` 明确标注），**不用「20日收益」冒充**。
  价格与收益计算用 `Decimal`（I/O 标准化后），输出保留 4 位小数。
- **相对表现**：`relative_return_pp`（区间收益差，单位**百分点**）仅在板块与基准对同一
  期望窗口**均 20/20 合格**时计算——两源日期集必须完全一致；任何一侧不足 20 天或日期
  不齐时各自保留有资格部分（如板块合格而基准缺失：板块区间收益照常输出、相对差为 null
  并注明原因），不伪相对比较。百分点是区间收益之差，**不是相对收益率**。
- **局部失败**：板块侧与基准侧各自有界（同一取数截止）；供应商失败/超时/取数预算耗尽
  只降对应块，已取得内容保留（如板块日线取得后基准阶段预算耗尽：板块区间收益保留），
  不拖垮整份报告、不留到总截止收尾之外。基准失败但板块区间收益已取得时报告完整性仍为
  complete（相对比较的缺口由块内/顶层缺口如实标注）；**板块侧趋势核心未取得则 partial**。

### 同业比较（issue #82）

- **资格**：与趋势块一致，只有 `confirmed` 才选取样本；资格满足而成分快照未取得时
  样本为空 + 缺口（数据未取得与资格不足分开表达）。
- **同一快照**：复用身份阶段成分验证的**同一次成分表请求**（快照另记采集时点
  `snapshot_observed_at`），不二次出站、不引入盘中漂移；内部 DataFrame 只是编排
  中间值，不进入严格载荷。
- **选取规则**（固定文案随载荷输出）：同一成分快照按**成交额前五 + 目标股去重**，
  称「成交活跃代表」。目标在前五内则样本 5 家，否则 6 家（目标殿后加入）。
  排序：成交额降序、并列按代码升序（稳定可解释）。**不称市值/基本面龙头**，
  不逐股补市值、不混用申万权重。
- **行资格与成员资格分开**：成员资格 = 6 位数字代码且无重复冲突；成交额可排名资格另需
  成交额为有限正数（原始值直接经 `Decimal` 判定，金融排序不经 float 中转）。
  缺失/0/负/非有限成交额的行**不参与成交额排名**，但其分类计数（缺失/零或负/非数值）
  在过滤**前**统计并随载荷（`snapshot_rows` 观测行数 / `rankable_rows` 可排名行数）与
  缺口暴露——**剩余可排名行充足（≥5）也不吞限制**。目标股成交额缺失/无效时目标成员
  仍保留（`amount=null` + 缺口，`target_in_amount_top5=null` 不误报非成员）。
  成分快照重复代码冲突整组剔除记缺口（目标股重复时目标不加入样本、位置不输出）；
  供应商空白/缺失名称在边界适配为**代码显示 + 缺口**（其余有效成员与报告不受影响，
  不整篇失败）；成分快照**无成交额列**与逐行金额缺失同语义处理：成员资格保留、
  成交额均为 null、不产成交额前五（不把未知金额成员列成伪 top5），已确认目标股
  仍带代码/名称/涨跌幅等实际字段保留在样本中，并明确缺口说明无成交活跃代表、
  不补 0 当数据。
- **成交额单位**：`amount_unit="元"` 随载荷输出，判定依据见 `amount_provenance`——
  已装 AkShare 的成分接口与全市场快照接口同为东财 clist `f6` 字段且 `fltt=2`、原样
  映射「成交额」；官方行情文档标注全市场快照成交额为元，板块接口文档未标注单位，
  **按同字段同接口参数推断为元**（诚实标注推断来源，不冒称板块文档明示）。
  正文样本表表头为「当日成交额（元）」。
- **目标位置**：目标股在样本内按**快照当日涨跌幅**降序的名次（= 严格更高的个数 + 1，
  并列同名次，与当日行情全表排名同规则）。目标涨跌幅缺失时位置为 null + 缺口（不按其他
  指标顶替）；**样本内存在涨跌幅缺失的同行时不输出全样本名次**（withhold），缺口披露
  有效比较范围（如 1/6 家），不把缺失同行默默排到目标之后；**样本仅目标股自身**
  （无成交额数据可选代表或无可比同行）时同样不输出名次（不产 1/1 伪名次），缺口说明
  比较范围不足。**快照当日口径与 20 日趋势窗口是不同时间口径**，正文分开标注；快照当日
  涨跌幅/成交额是成分接口实际返回字段，不为本票扩个股基本面研究。

### 资料状态：未评分 ≠ 资料不足 ≠ 完整性缺口

| 字段 | 含义 | 触发 |
| --- | --- | --- |
| `assessment.status = unscored`（未评分） | 有可研究主体，首版不产出综合评分——**这是评分政策**，可带缺口 | 主行业身份 confirmed / unverified |
| `assessment.status = insufficient_data`（资料不足） | 核心问题无法回答，不产出任何评分/分档/行动建议 | 主行业身份 missing / ambiguous（无行业数据、板块表无精确命中或多候选） |
| `assessment.completeness = complete / partial`（完整性） | **这是资料状态**：动态事实（当日行情、板块趋势、同业样本）的实际取得情况，与评分政策分开 | 判定规则（issue #81 第二轮；issue #82 起缺口原因**累积可见**而非短路）：`insufficient_data` → partial；当日行情未命中 → partial + 原因；行情行存在但核心动态（涨跌幅/动量）未取得 → partial +「动态字段未取得」原因；成分 unverified（归属未确认）→ partial；confirmed 但**板块趋势核心未取得**（日历不可用/供应商失败/预算耗尽/数据不合格）→ partial +「板块近期趋势未取得」原因；confirmed 但**同业样本为空** → partial +「同业样本未取得」原因；其余（confirmed + 行情命中 + 动量有效 + 趋势/同业取得）→ complete。部分可选维度缺口（如东财正常表无成交额列、同行涨跌幅缺失时的全表排名资格、同业样本不足 5 家、基准失败但板块区间收益已取得）由 gaps 如实标注，不机械降级整份报告 |

完整性原因累积而非短路：行情动量缺失不再掩盖趋势/同业核心缺口的原因——多个独立缺口
各自进入 `assessment.reasons`（上限 10 条），缺失状态与实际有效性一致。

主行业身份四个状态贯穿载荷、正文、页面与存档：`confirmed`（板块锁定且成分验证通过）、
`unverified`（板块锁定但成分验证失败或不含目标股——归属未确认，报告继续但缺口醒目）、
`ambiguous`（无法唯一锁定，**不按近似名取首行**）、`missing`（无行业数据）。
部分数据缺失的报告按「部分报告」原则保留有效内容并列出具体缺口。
分类元数据：`classification_system` 标注锁定口径（东财行业板块）；
`classification_level`/`classification_version` 供应商未返回时恒为 None，正文如实标
「未知（供应商未返回，不推算）」。

### 当日行情的同一主体命中（同键唯一）

身份锁定板块代码后，当日行情命中行必须与身份锁定**同键唯一**（板块代码一致**且**
板块名称一致）：同键恰 1 行才命中；同键多行（重复同键）、代码命中但无同名行
（同代码错名/快照漂移）、行情表缺代码列（同键不成立）都记缺口，**绝不取首行**、
不回退名称或近似名（反例：同快照 [错误行业/BK1277, 白酒Ⅱ/BK1277] 时首行会把
行情绑到错误行业）。身份与当日行情复用同一板块全表快照，不因二次查询产生盘中漂移。
无代码时按唯一精确名称（多行命中不可锁定、不取首行）。

### 数据时间口径

- `observed_at`：本系统采集时点；`vendor_as_of`：供应商数据截止时点。东财/akshare 渠道
  未回显 as_of 时保持「未提供」，不用采集时间顶替。
- 申万参考链、巨潮证监会行业与 iFinD 分类属于不同分类体系/层级，只作参考单列；
  跨体系不做成分或行情拼接。

### 相关概念的展示截取

供应商合法返回超过展示上限（50 条）时：`items` 截取展示、`total_returned` 保留原始
总量、`truncated=true` 且缺口注明「展示截取，非供应商故障」。概念入口停用/失败/取数
预算不足均记缺口，不影响主报告（可选阶段隔离）。

## 生成与反馈

- **编排顺序（issue #82/#83 预算纪律）**：主行业身份（必需）→ 趋势/同业（必需新块，
  confirmed 才发出站）→ 当日行情（身份快照本地计算）→ **催化搜索与证据化综合**
  （issue #83 必需研究，confirmed 才发出站；综合依赖催化结果）→ 申万参考链/概念
  （可选长链）→ 政策/基率（本地）。必需研究先于可选长链出站，可选阶段耗尽取数预算
  不会让必需研究根本不尝试；各块自身失败只降对应块，已取得内容保留走总截止收尾。
- 生成入口沿用既有 `POST /api/v1/sector-analysis/generate?stock_code=&stock_name=` query 参数。
  未携带 `stock_name` 时名称如实用股票代码，**不为补名调用共享行情 manager**（其内部多源
  fallback 不感知报告预算，曾在取数截止后仍启动新数据源）；页面与常规调用均显式携带名称。
- **报告总预算**：`SECTOR_ANALYSIS_REPORT_TIMEOUT_SECONDS`（默认 300 秒，允许 1—300，
  越界按边界 clamp）。取数/重试/等待共用同一剩余预算，且全部按**取数截止**钳制——
  收尾余量上限 5 秒、随预算缩放为 `min(5, 总预算/2)`（渲染/严格校验/持久化的预留，模块
  常量非配置；1—5 秒合法小预算下留一半给取数，不会在起点即耗尽）。
  渲染前/渲染后/写入后分别检查主截止。预算耗尽时本次终止——**不存档、不留文件、
  不采纳晚到结果**；已放弃等待的供应商在途调用可能仍在进行，其结果不会被采纳
  （等待钳制不伪装硬截止）。供应商自身的 TimeoutError 按局部来源错误记缺口，
  不谎报预算耗尽。
- **写盘与 DB 提交同一截止**（issue #81 第三轮）：文件写入本身可能迟到（慢盘/负载），
  写入完成后复核主截止，过期即清理本请求独占文件、不开始 DB 保存；板块保存入口
  （`save_sector_analysis_report` 的可选 `deadline`）把同一 monotonic 截止纳入真实
  SQLite 事务——deadline 路径由本请求**独占持有**一条物理连接（ORM 写入经
  `Session(bind=…)` 全走该连接），锁等待按剩余时间经 `PRAGMA busy_timeout` 钳制
  （flush 前与提交前分别按剩余时间钳制）；真实 INSERT 经**显式 flush** 提前发生，
  **flush 后复核同一截止，过期即 rollback 不提交**；锁超时返回失败；**commit 一旦
  成功即如实成功，不存在提交后再伪报超时的路径**。连接归还池之前恢复原
  busy_timeout——成功/失败/超期路径一致，请求级锁等待不泄漏给共享池的其他写入。
  能力边界如实声明：这是有界**同步**提交，不是 OS 层硬截止；SQLite 方言的锁等待由
  busy_timeout 钳制（可检查的截止边界覆盖到真实 INSERT/flush 之后），其他方言仅
  提交前检查。`deadline` 缺省（None）时该方法行为与既有调用完全一致，不影响其他
  调用者。失败响应如实区分供应商超时/取数截止/总截止耗尽/保存故障。
- 生成终态精确反馈，不假成功：
  - 成功 → 200 + 完整载荷（部分报告同样 200，缺口随载荷透出）；
  - 预算耗尽 → HTTP 504（未保存报告，可重试）；
  - 保存失败/载荷校验失败 → HTTP 500（不返回成功、不留孤儿文件）。
- 存档提交边界：严格载荷校验先于任何写文件/写库动作；报告 ID/文件经
  原子独占创建（同分钟并发请求各自拥有独立 ID/文件），任何失败只清理本请求
  独占创建的新文件，不触碰他人存档。
- 页面等待上限 330 秒（前端固定）：等待超时或连接中断时提示「生成可能仍在后台进行，
  稍后可刷新历史查看」，与处理失败、保存失败分开表达；生成中防重复提交。
- 历史/详情/删除/下载失败均有可见错误提示：详情存档文件缺失返回明确 500（不吞异常
  返回 200 空正文）；下载/查看原文件经统一 API 客户端取回（同基址与认证语义），
  失败在页面可见（blob 错误体在页面内局部解析服务端 message/detail，不再显示空对象）；
  下载 Markdown 读存档原文，不重新生成。
- **删除如实反馈部分失败**：记录已删除但存档文件清理失败（OSError）时，响应为
  200 + `file_cleanup="failed"` + 可理解 `message`（「记录已删除，但存档文件清理失败」），
  页面如实展示——不静默假成功，也不需要跨存储事务；重复删除返回 404。
- 移动端历史抽屉的删除控件默认可见可点击（不依赖 hover），桌面端（sm+）保留悬停浮现；
  控件带 aria-label 与触控内边距。

## 兼容与回滚

- **生成载荷追加兼容（非整体换形）**：v2 字段之外保留旧路径最小兼容投影——
  `analysis.identification`/`analysis.policy`/`analysis.base_rate`/`analysis.prosperity`
  为旧非评分事实路径（既有调用者仍可读，事实自 v2 字段投影）；旧评分字段
  `analysis.sector_score`/`band`/`beta_meaning`/`weights`/`prosperity_score` 保留路径但
  **显式退役（恒为 null）**——新报告不恢复旧综合总分、旧分档或行动结论；
  `policy.score`/`prosperity.capital` 同为显式 null 退役（政策档位分易与综合评分混淆、
  旧「资金」维度实为成交额分位已更名 `amount_activity`，回填会重新引入净流入误读）。
- **issue #82 追加块**：`analysis.sector_trend`/`analysis.sector_peers` 为新增顶层
  可选默认键（compose 新报告总是产出，资格不足时 `eligible=false` + 未执行原因）；
  已验收 #81 形状载荷（缺新键）仍通过严格校验（追加兼容）。存量旧记录经
  详情端点以自由 dict 透出、缺新键仍可读；页面渲染 Markdown 存档原文，新章节只
  影响新报告。无存储迁移。
- **issue #83 追加块**：`analysis.sector_catalysts`/`analysis.sector_synthesis` 为新增
  顶层可选默认键（同 #82 追加兼容边界；`sector_catalysts.items[].date_basis_detail`、
  `sector_catalysts.items[].final_url`、`sector_catalysts.background_items[].final_url`、
  `sector_catalysts.dropped_invalid_field`、`sector_synthesis.claims[].evidence_refs`、
  `sector_synthesis.rejected_count` 等子结构均可选/带默认；`source_domain` 上限 253
  为完整 hostname 边界）。已验收 #81/#82 形状载荷（缺新键）仍通过严格校验；存量旧
  记录缺新键仍可读；无存储迁移。共享 adapter 的 `propagate_program_errors` 为
  **默认 False 的可选关键字**——全部既有调用方行为逐字节不变，仅板块综合显式
  opt-in；共享 `SearchResponse.malformed_rows` 为追加默认 0 的元数据字段——既有

  无破坏性迁移、无数据删除。
