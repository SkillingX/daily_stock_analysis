# Domain docs

## 布局

本仓库采用 single-context：领域术语位于根目录 `GLOSSARY.md`，架构决策位于根目录下的 `docs/adr/`。Web、Desktop 和后端目录共同使用这份术语约定，不因存在多个应用目录就拆成多份领域模型。

## 阅读规则

探索相关实现前，若根目录 `GLOSSARY.md` 存在，先阅读；再阅读 `docs/adr/` 中与改动有关的决策。

文件尚不存在时直接继续，不将缺失当作阻塞，不预先创建空白文件或模板目录。仅在实际术语或决策得到确认时，由领域建模工作按需补充。

若将来明确迁移到 multi-context，根目录 `GLOSSARY-MAP.md` 应指向各上下文的术语表；读取相关上下文及其 ADR，同时遵守全局 ADR。存在地图时以地图确定阅读范围，不猜测目录分区。

## 使用约定

工单标题、规格、测试名称与代码讨论采用术语表中已有用词，避免无意引入同义概念。真实术语缺口留给领域建模，不为一次修复扩建术语体系。

方案与既有 ADR 冲突时，指出决策编号及冲突原因，不能静默覆盖。协作和权限规则仍以 `AGENTS.md` 为准。
