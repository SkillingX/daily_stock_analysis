# 基本面数据与报告质量

基本面专项与双轨 F1 复用共享快照。数值 `0` 和负数是已取得的数据，只有 `None` 表示缺失；报告不把零增长或零盈利指标显示成缺失。

共享快照的 `market_cap` 优先读取数据源规范字段 `total_mv`，兼容 `market_cap`、`total_market_cap`。PE 优先读取 `pe_ratio`，缺失时使用 `pe_ttm`；营收同比优先读取 `revenue_yoy`，缺失时使用 `revenue_growth`。别名补值不覆盖已有零值，不改变原始单位或既有评分分档。

`get_stock_info` 估值备用抓取只在 PE、PB、总市值或流通市值存在 `None` 时触发，也只补 `None` 字段。四项均为零时不额外抓取，部分缺项时保留其他已有零值。

旧阶段 0 基本面快照可能已经丢失零值或市值。修复后的快照使用独立版本的缓存键；F1、六维评分和情景维度拒绝没有新映射版本标记的旧缓存。其他业务、行业等缓存仍可复用，不批量删除缓存或修改历史报告。已保存报告仍保留生成时的内容。

离线回归：`python -m pytest tests/test_fundamentals_data_quality.py`。测试通过源响应替身，保留真实 manager、共享快照、F1 规则和专项模板；不会证明在线供应商当前的完整性。

## 财务表与报告期

AkShare 财务适配器支持“指标 × 报告日期”的转置表，以及“报告日期 × 指标列”的行式备用表。一次选择源响应中已证实的最新期末，所有字段都从这一期读取；2026-06-30 与 2025-12-31 均有效时选择前者，列/行乱序不改变结果。最新期缺项保留缺口，不借旧期数值拼齐。

`growth` 保留营收同比、归母净利同比、ROE、毛利率，并追加实际 `report_date`；`earnings.financial_report` 读取同一期的营收、归母净利、经营现金流、ROE 和 `report_date`。金额标签不能匹配同名增长率。数值零、负数保留，NaN/无穷数视为不可用。只出现一个未注明日期的观测时可保留单项值，期间仍为 `None`；多个无法辨认的期间或全无可用指标会留下明确错误，不伪造完整财报。

转置表可在多个分类下重复展示同一指标。同一期重复值一致时保留一次；相互矛盾时该指标不可用，并在 `errors` 记录重复冲突，不选首项或平均。金额只匹配确证的完整指标名称：利润率、扣非净利、未区分归属的净利润不当作归母净利金额。报告日期是元信息，不会使全缺的增长块升级成 `ok`。

当前 bundle 没有用户报告期参数，本次不新增报告期入口。核验 Source 已有的请求期间及实际期校验另由核验层处理，不能从请求文字替代源响应的实际期。上述表形与链路由合成原始响应验证，未取得线上脱敏响应，无法证明供应商今日的表形或故障频率。

同期表解析的修复同时升级基本面映射版本；旧阶段 0、F1、六维和情景缓存不再复用，其余维度与历史报告保留。回滚修复提交可恢复旧解析，无数据迁移。

## 实际期间与口径

MX、iFinD、Choice MCP 和 Fuyao 的读数 `period` 表示源响应确认的实际期末日，统一成 `YYYY-MM-DD`；`requested_period` 单独保留取数请求。请求 2025 年报而返回 2026 中报时，值属于 2026-06-30，不能贴上年报标签。指定期存在时优先选择该期；不存在时可读取实际最新期，仍保留请求与实际期间的差别。

`period_basis` 区分 `annual`、`YTD`、`single_quarter`、`unknown`。年报或明确 annual 响应可证实全年；只有日期而没有累计/单季证据时保持 unknown。同一期末的累计与单季不能严格同期核验；请求文字不作为实际期间或口径证明，普通数字和无关文本不会被扫描成年报日期。

财务金额、ROE、毛利率及同比核验要求实际期、期间基础及指标口径都已确认相容。未知或异期保留主值，置信度为 medium、agreed=false；这不自动取消有效主值的局部分析资格。PE/PB 不使用财务报告期条件；TTM 仅来自返回字段的明确标识，Fuyao 的 `pb_mrq` 为 MRQ，通用“市净率/最新”字段不会被补成 TTM。

指标身份完整匹配现有明确定义；单位、单季/累计和公布值注记不改变身份。毛利率同比、加权 ROE 同比或“比上年同期增减”不能充当指标水平，未加权 ROE 不能冒充加权 ROE；营收和归母净利同比须返回字段明确标有“同比”或 YoY，复合增长率/CAGR、环比及未定义比较方式的增长率不得充当同比。MX 和 AkShare 的营收、归母净利预筛复用集中身份判定，明确同比/YoY 不要求同时出现“增长率”后缀；零值和负值贯通共享快照及 F1。同一响应有真实指标列时采用真实列，合法零值和负值保持；仅有异定义读数时不能用于核验通过或相关评分。修复后的财务缓存版本拒读旧字段资格，业务、行业缓存和已保存报告保持。

读数追加可空的 `observed_at`、`fetched_at`，包装和精简输出保留已取得的证据。取得时间不是数据发生时间；缺证据仍是未知。期间契约修复升级基本面及依赖维度缓存版本，旧历史报告保持原样。关闭核验仍不新增核验请求；跨源家族、全部读数核验与单位校验由后续修复收敛。
## 财务期间证据的优先级

供应商显式 `period_basis` 与字段中的“单季/累计”优先于通用中报、年报标签推导的期间口径。单数字月日与补零日期等价；实际数据时间从供应商已有日期/时间字段保留，不将其视为财务报告期。指定期目标字段为空时，独立锚点可选择同一响应中已确认的最新有效期间，仍保留原请求期与实际回退期。

## 核验读数的单位与币种

MX、iFinD、Choice 和 Fuyao 的核验读数同时读取单元格与返回字段单位。货币量使用 `currency_base`，百分比使用 `percentage_point`，估值使用 `multiple`；明确 `ratio` 的 0.18 转为 18 个百分点，单独的 0.18 保留原值并标记单位未知。金额缩放通过 `Decimal`，在既有 JSON number 边界转为有限数值。

金额量级与币种名称一起识别：2 亿美元和 2 亿港元分别规范为 200,000,000 USD/HKD，2 万日元为 20,000 JPY；零值、负值和科学计数同样保留正确倍率。单位可来自表头、显式 unit 或数值后缀，均需完整识别声明；未知币种词夹在量级与单位之间，或十万等未支持声明只被部分匹配时，拒绝单位准入，不取末尾“元”或较小倍率。矛盾单位与币种仍拒用，不做汇兑；修复前的财务缓存资格不再复用。

`unit`、`currency`、`raw_value`、`raw_label`、显式声明的 `raw_unit` / `raw_currency` 与 `normalization_error` 随 Source 包装及 compact 保留。表头万元与数值亿元矛盾、金额币种未知或币种不同均不可比；不会自动汇兑或默认人民币。百分比和倍数不要求币种。未规范化的原值保留作证据，不代表规则可用。旧期间版本 4 的核验缓存也不再复用；不修改历史报告或数据库。

## 全源证据与核验状态

核验保留既选主值，全部已取得读数进入 `readings`，失败和超时进入 `source_errors`。同实际期、口径、单位及适用时间的全部有效对参加容差检查；第三、第四源及未知家族的可比读数也会揭示冲突。任何可比对冲突都保留主值作证据并返回 `conflict/low/false`，不会多数投票、平均或换主值。异期或异口径额外读数单列不可比，不否定其他已证明独立的佐证。

MX/Choice 属东财家族，iFinD/Fuyao 属同花顺家族；家族只限制独立佐证资格。未知家族不算独立票，但不会从数值冲突检查中排除。`verified/high/true` 需要相对于主源的已知独立家族；同家族一致只有 `single_source/medium/false`。其他状态为 `missing/low/false`、`unverified/medium/false`、`not_comparable/medium/false`，原因使用稳定 `reason_codes`。`conf` 与 `v` 继续作为兼容字段，证据值不等于允许评分。

行情和资金的时间取自 `observed_at`，不能用 `fetched_at` 补证。行情须有完整数据时间且未超出现有 `REALTIME_CACHE_TTL`；融资余额使用既有市场有效交易日。财务使用实际财期，不要求抓取秒相同。资金流只核验方向相同及量级差不超过原一档；相邻档可通过，零值不能作非零方向证明，也不能掩盖其他源反向冲突。

截止前返回的读数仍参加判定，未完成源明确超时，核验返回不等待慢源结束。每个现有 validator 复用固定上限的取数线程池；已过截止不提交新调用。具体底层调用预算传递由补缺流程统一处理。关闭当前核验开关后不会使用进程缓存 validator 联网，财务快照及 F1/六维/情景缓存按当前核验模式隔离，业务和行业缓存保留。

## 采用值与字段证据

manager 的 quote 合并、基本面主备源和三个数据工具通过 `field_meta` 保留每个已采用字段的真实来源、报告期、口径、单位、币种、数据时间与选择理由。旧 scalar 保留，包括 0、负数和冲突证据；核验的 `v` 使用同一个精确采用值，不因 compact 四舍五入产生另一份事实。冲突字段的 `rule_eligible=false`，不能作为普通缺项回填。PE 未证明 TTM、PB 未证明 MRQ、ROE 未证明加权口径同样不能进入相应规则。

备用 Source 的 reading 不再降成 float 后丢掉出处；已取得 MX batch 与逐字段 Source 使用同一个解析入口。未知元信息明确保留未知，不把主 quote 来源或整块 `as_of` 套给补充字段。旧基本面上下文和映射缓存按版本拒读；回滚不需清理历史报告或数据库。本专题新增中文说明，没有对应英文专题文件，不修改首页 README。

## 缺项补取与阶段预算

增长四项分别判缺，顺序为块内已取得主值、主源本次已取得的 earnings 财报字段、现有备用源、MX。只有缺失字段请求备用，0 和非空冲突证据保持原值；候选复用字段准入，未知期间的有效独立字段可局部使用，不据此宣称同期财报。明确异定义、未知单位、已知过期或冲突候选不补值。公开完整度和评分限制由 F1 品质消费层展示。

所有财务取数使用现有阶段配置的同一个截止时间，单次不超过现有 fetch 配置与真实剩余时间；零余量不新取数或重试。正常缺项备用取数与 opt-in 核验分开，关闭核验仍允许前者。MX/Fuyao 的显式重试与 MCP 调用、关闭连接均受剩余时间限制，使用 SDK 自带 HTTP 客户端适配现有支持的 transport API。SharedContext 的直接 Fuyao HTTP 与 JSON 读取也复用 manager 已有有界超时执行，不将 requests 的逐次读取超时误作总预算。慢源超时不在退出时等待完成，已有主字段保持可见。

旧 SDK 没有 timeout 参数时，复用现有请求补丁入口的任务局部 ContextVar，仅当前财务线程的 requests 调用受预算约束；没有任务预算的请求保留原 timeout，东方财富认证补丁继续由原开关控制。首次并发安装补丁时原子检查和安装，包装函数捕获安装前的请求函数，避免后续全局引用变化造成递归。efinance 与核验器复用固定 worker 上限，阶段 worker 的原八槽上限保留；没有新增调度平台或配置项。缓存映射和 manager 事实版本更新，不清理历史数据。

## 报告品质与评分

同一源响应同时包含泛化 PE/ROE 与明确 TTM/加权指标时，解析器优先选择字段自身获准的定义；没有获准候选时仍保留有限原证据及限制。实时行情时间标注、股票工具、资金工具再次投影时，保留与当前采用值绑定的 conflict，不能把它重置为 unverified 并恢复规则资格。默认核验复用 manager 已有 MXSource 的响应缓存，保留其他独立通道；同一次财务取数不通过新客户端重复请求已取得的相同查询。

配置热重载重置 manager 时同步重置核验器，下次使用新 manager 的 MXSource，避免保留旧源配置和重复客户端。Longbridge 只有实际采用 `eps_ttm` 计算的 PE 声明 TTM；普通 EPS 的计算值保留为口径未知。

专项与双轨 F1 共用 SharedContext 的采用值与已有核验器。关闭核验时不产生核验请求，有值显示 unverified；开启时每字段仅执行一次核验，全部字段共用财务阶段截止。当前采用值被完整保留，conflict 或自身口径、单位无效的字段不能进入健康、直接估值、增长剪刀差或情景 PE 公式。未知家族的可比离群值仍会触发冲突。净利除期末权益的 Fuyao 派生比例仅在实际期及金额单位、币种相容时保留，显示计算定义，不充当加权 ROE。

财务质量独立于报告保存状态 success / failed / already_exists。取得 n/6 的分母固定为 PE、PB、ROE、毛利率、营收同比、归母净利同比，有限零值、负值、冲突值均算取得；规则可用 m/6 只计获准字段。n=0 为 none，1..5 为 partial，6 为 complete，complete 不代表 verified。

健康分保留 ROE、毛利率、营收增长、净利增长、估值五组件的可得均值，展示参与 k/5；估值优先正 TTM PE，否则正 MRQ PB。k=0 健康分为 None，六维对应指标按既有缺项纪律展示中性 50 / low / data_gap。唯一营收同比 10 得到 n=1、m=1、k=1、健康分 65，只作局部评估。m=6 且 k=5 才称组件完整评估；组件完整不等于同期财报或全部独立核验。不同实际期或累计/单季不相容的增长指标保留单项评分，不计算剪刀差。规则评分置信度与跨源核验状态分别解释。

API dims 与两类 Markdown 展示每字段来源、实际期、口径、单位、核验限制及规则资格。普通 AnalysisContextPack 的公开摘要仅透传已有六字段的低敏质量元信息，不暴露原响应或数值，不新增取数与核验。历史无品质元信息的专项报告在读取、复用和下载时追加未核验提示，原文件与数据库不重写。财务相关缓存按映射版本隔离；启用核验时重新取当前证据并重算相关派生规则，其他维度缓存仍可读。回滚不需清库，旧代码拒读映射版本不符的财务缓存。

离线入口回归：`python -m pytest tests/test_f1_financial_quality.py`。覆盖 SharedContext 真实开关、慢源退出、F1 及具名规则、专项 service/API/存储、两类实际模板与公开摘要。供应商与 LLM 使用隔离替身，结果不证明在线供应商完整性或生产验收。

## 显式刷新与历史版本

基本面专项页面的“生成报告”默认复用当天最新保存成功版本。上游恢复后，选择股票并点击“刷新数据并生成新报告”，会绕过该股票本次财务查询的 MX 原响应缓存（包括旧缺项和错误响应）、manager 基本面缓存、阶段 0 财务快照和同日复用，并即时重算 F1。用于估值的 efinance/AkShare A股或ETF原行情响应缓存也按目标刷新标记绕过；本次新响应不覆盖全市场缓存，其他股票与普通请求仍按原 TTL 读取。业务画像也绕过维度缓存，行业仍由规则计算；不删除缓存或历史 financial 数据。同一刷新内部相同 MX 查询可复用本次新响应，不给每字段重复发相同请求。

API 兼容增加 `POST /api/v1/fundamentals/generate?stock_code=600519&force_refresh=true`，省略或 `force_refresh=false` 保持复用；只接受小写 `true` / `false`，其他值返回 422。认证边界不变，响应保留 success、failed、already_exists，并追加 partial：报告已保存但至少一个研究维度未完成。success 表示各维度状态均为 ok，仍不代表字段完整或交叉核验通过，品质以 dims / Markdown 说明为准。

每次明确刷新生成独立 ID、文件和记录。旧 ID 及新追加的数字后缀 ID 都保持原读取契约；两次并发刷新可保存两个版本。列表与默认复用统一按已有 created_at 降序、同时间按 ID 降序，created_at 在本次生成开始时记录，不按保存完成顺序重排。生成异常或保存失败保留旧成功版；保存失败的本次文件清理，不覆盖历史。前端同一在途操作防重复提交，POST 不自动重试，另一次点击表示新意图。连接超时不能证明服务未保存，可先刷新历史列表确认；不承诺 HTTP exactly-once。

离线恢复/失败/并发与真实缓存验收：`python -m pytest tests/test_fundamentals_refresh.py`；页面在途与失败行为：在 `apps/dsa-web` 执行 `npm run test -- src/pages/__tests__/FundamentalsPage.test.tsx`。回滚本提交恢复原 API/Web 与复用策略，旧读取器仍可按 ID 读取这些追加版本，无需删除记录或清库。本专题没有配对英文文件。

## 生成时限与取数补查

基本面专项保持同步接口与原五章模板。`FUNDAMENTALS_REPORT_TIMEOUT_SECONDS` 默认 300 秒，允许 1–300 秒（超界按配置解析器限制）；页面等待 330 秒，留出渲染、SQLite 落库及传输时间。显式配置 150 等较短预算仍生效，旧部署需要主动修改该值并重启对应 API 才会使用 300 秒。预算从服务入口开始，阶段零、业务画像、等待模型并发额度和 JSON 修复消耗同一单调时钟截止时间。单次 `LLM_STREAM_RESPONSE_TIMEOUT` 不能延长更短的报告剩余预算；已有进程并发和阶段零时限不变。未完成的业务画像按 degraded 记录原因，其余已取得数据仍可生成 partial 报告，历史版本保留。必要保存与传输可能有少量收尾开销，结束本地等待不表示供应商后台必然停止计算。未提供名称时复用阶段零行情中的名称，并同步共享上下文供板块规则使用；仍缺失才以代码显示，避免预算之外另做行情查询。阶段零等待按自己的阶段截止时间结束，不借用后续研究预算；迟到的 IO 结果不再采纳。

业务画像的最后成文使用已取得证据，对实际供应商模型为 MiniMax-M3 的 OpenAI 兼容调用显式关闭 thinking，首轮工具规划保留原参数。基本面专项和深度投研共享此业务画像行为；其他研究员及 Kimi/GLM 等模型不变。按实际模型而非配置别名识别，多部署别名只有全部目标模型均支持时才应用；非目标 fallback 不继承此参数。来源、缺口与严格业务校验仍保留，截断输出不计成功。

页面区分客户端等待超时与服务端明确的上游失败。生成请求报错后自动刷新一次历史列表，保留此前显示的报告，让用户自行选择已保存版本，不自动重发或把最新历史认作本次成功。历史刷新失败单独提示，不覆盖生成错误，也不把已经成功保存的报告误报成生成失败。后端和前端需配套发布，核对部署代理没有更短的显式等待限制；本专题没有配对英文文件，无需扩展 README。

Agent 在明确传入 timeout 时关闭 Router/SDK 内部重试及 Router 隐式 fallback；配置的模型 fallback 仍由 adapter 按剩余时间逐个尝试。模型调用失败、超时、步数耗尽不会按 JSON 格式错误整轮重跑；只有成功返回但 JSON 非法才在剩余预算内修复一次。日志记录模型轮次、调用预算和耗时，不记录凭据或完整提示词。这里约束同步调用与重试预算；底层同步供应商 IO 若不遵守超时，Python 无法强制中断其线程，已发出的供应商请求也无法承诺撤销或退费。超时的取数结果不回写已返回上下文，不再启动后续模型轮次。

综合情报按每个维度尝试配置好的来源；失败或过滤后无有效结果时，才尝试下一个来源，公共 SearXNG 和 HTML 抓取放在后备位置。一次维度内每个来源最多尝试一次（供应商内部原有重试不变）；Agent 工具截止时间到达后不再启动新的维度或来源。HTML 公告抓取无需 API Key，已从基类凭据检查中豁免。

阶段零财务取数与交叉核验仍共用 `FUNDAMENTAL_STAGE_TIMEOUT_SECONDS`：启用核验时为核验预留不超过单源超时且不超过总预算一半的时间。manager 和后续 Fuyao 补值共用扣除预留后的取数截止时间；取数耗尽后直接进入核验，不允许补值占用预留时间。manager 在已配置 MX 时，为其保留不超过单源超时且不超过 manager 预算三分之一的时间。MX 只补缺失财务及 PE/PB 字段，复用既有批量查询缓存，不覆盖已有零值；财务批次已足够时不再发财务查询。

新浪 `stock_financial_abstract` 的已核实标签 `净资产收益率(ROE)`、`毛利率`、`营业总收入增长率`、`归属母公司净利润增长率` 恢复百分比百分点单位，ROE 明确为加权，来源家族为 sina；该接口报告期序列的年末为 annual、季末为累计 YTD。依据为 [AKShare 关键指标接口说明](https://akshare.akfamily.xyz/data/stock/stock.html)、安装包对新浪 `CompanyFinanceService.getFinanceReport2022` 的调用及 2026-10-12 原始响应的 `ROEWEIGHTED`、`SGPMARGIN`、`TAGRT`、`NPGRT` 字段。仅恢复这四个精确标签的接口契约；其他接口、未知标签和金额单位仍保留 unknown。元数据完整不自动升级为跨源 verified，必须经过实际独立来源比对。

回归：`python -m pytest tests/test_fundamentals_generation_budget.py tests/test_search_comprehensive_intel.py tests/test_fundamentals_data_quality.py tests/test_fundamentals_refresh.py`。包含本机 HTTP 服务拖延响应、真实 LiteLLM Router/SDK 无叠加重试、报告 API 部分结果保存与重开、慢行情不挤占 MX、无 Key 抓取器进入真实抓取入口的受控验证。没有配对英文专题，无需同步 README；无数据库迁移，回滚对应源码并重启即可恢复原行为。

### 业务画像的资料边界

业务画像默认 prompt 随源码存放在 `src/deep_research_dims/prompts/business.md`，Docker 镜像同样包含，独立空 data 卷不影响加载。非空 `data/deep_research/agents/business.md` 可覆盖默认内容；默认文件和覆盖均不可用时明确降级，不发无约束模型请求。

业务画像采用独立 prompt，只研究主营、产品和竞争地位，显式提供分析日期；不继承终稿强制评级/目标价要求。使用现有综合搜索的 business profile，围绕三个业务问题查找资料，省去重复最新新闻和缺乏同口径依据的大盘查询。其他调用默认仍走原综合情报路径。

业务 profile 只向模型提供结构化资料，保留 URL、来源和发布日期；日期未知保持未知，已知过期资料按分析资料窗口过滤。来源等级须根据实际出处判断，不把检索渠道或相关性分数当作核验。模型须在既有业务字段/narrative 中保留证据链接和时点，报告展示业务 data_gaps；不新增会被解析器丢弃的来源字段。结构成功不等于事实已核验，也不保证旧报告自动获得新证据。

### 搜索与最终生成的预算

基本面业务画像把进入研究时的剩余时间分为两段：前 1/3 用于规划和资料工具，后 2/3 保留给最终生成。规划和工具共享同一绝对截止时间，不按工具/轮次重新计时；实际查询提前完成即可提前进入收尾。业务画像最多一轮工具批次加一轮最终生成，收尾请求不携带可调用工具，若供应商仍返回工具调用则明确失败，不执行它。其他 Agent 未传研究截止时间时保持原流程。

比例依据：本机原输入的 high 模式需要约 68–85 秒；收敛业务资料后的实测最终生成约 18–21 秒。给约 120–130 秒研究剩余预算保留约 80–87 秒，避免旧链路搜索耗去约 83 秒后只留约 41 秒。单次计时不是 SLA；慢源与模型响应均受总时限约束，不能靠无限重试保证“成功”。JSON 格式修复继续使用原总截止时间，并保持资料阶段已关闭，不再下发或执行搜索工具。

业务章节以可追溯的经营模式和主营产品/收入结构是否有效完成判断整章状态。仅缺未披露市场份额、客户或对标细项时保留具体 data_gaps，不因此把整章标为未完成，也不把占位文字当成有效内容。核心资料不足、模型未完成或来源不支持时仍限制整章，保留已取得内容和资料缺口，不写成功维度缓存；旧的同类业务缓存不复用。success 仍只表示结构化研究完成，不替代事实核验，也不提高财务规则资格。

模型的 length/content_filter 结束原因不作为完整报告成功；`force_refresh=true` 同时绕过业务维度缓存和当天报告复用，旧记录仍保留。资料缺失或不适用规则的财务字段继续显示 partial/degraded，不因 GLM 正常结束而改成全绿。

可复跑本机 API 验收：`python scripts/smoke_fundamentals.py --base-url http://localhost:8000 --stock-code 300260 --stock-name 新莱应材 --output <私有证据文件>`。该操作消耗数据源/模型额度并保存一个新报告，随后核对重新读取的 Markdown；退出 0 为完整 success，退出 2 表示已保存可重读的 partial，其他错误非零退出。页面打开历史列表可查看新版本。只对本机测试服务使用；不要把 partial 当成所有财务数据都已核验。

### 报告排版与历史兼容

基本面、个股财务和个股板块的新报告统一使用标准 Markdown（红点与加粗），不再加入 font 标签。Web 共用渲染组件仅移除旧报告中既定红色 font 包装，不开放任意 HTML；代码块和行内代码保持原文。

基本面业务对象复用中文格式化，value 按业务说明展示，嵌套对象和列表保留独立条目。历史基本面文件存在旧 font 包装且保存了完整的三个维度对象及报告日期时，仅根据保存的维度重新排版；日期、证据和缺口继续来自历史快照，不重新取数、调用模型或覆盖原文件。详情、当天复用和 Markdown 下载返回一致的排版结果。缺少历史结构化快照时保留原文，由 Web 兼容字体包装；旧的原始文件不做批量迁移。

回归：`python -m pytest tests/test_report_formatting.py`；Web 执行 `npm run test -- src/components/report/__tests__/ReportMarkdownBody.test.tsx`。覆盖新报告、历史详情/下载一致性、文件不变、列表/链接/表格与 HTML 安全边界。本专题无英文配对文档；未改 README。回滚对应源码并重启即可，数据库与历史文件无需恢复。

### 合并前反例回归

单位识别只接受独立或词尾的单位声明，不把“股东”等指标词误认成“股”；`归属母公司股东的净利润同比增长率=-7.518%` 保留负值与百分点单位。财务缓存映射版本更新，旧的误判资格不复用；已保存报告仍是历史快照，需刷新生成新版本。

有任务 deadline 的 requests 响应在每次底层 socket 读取前重算剩余时间，覆盖持续慢响应头、正文、chunk 头及 gzip 数据；超时由 requests 清理连接，工具线程退出。该实现复用 CPython HTTP/HTTPS 的 `SocketIO`，无 deadline 的调用不变，保留 Session、Cookie、重定向和流式消费。此边界不保证中断 DNS 解析、非 makefile 客户端、CPU 运算或第三方 SDK 自建线程；不能据此声称任何外部 IO 都可强制取消。

回归执行：`python -m pytest tests/test_fundamental_units_contract.py tests/test_f1_financial_quality.py tests/test_fundamentals_generation_budget.py`。慢流测试包含本机 HTTPS（需要 `openssl` 命令），不使用外部凭据；Docker CI 额外验证默认业务提示词可读。本专题没有英文配对文件。

## 取数超时与供应商不可用

核心财务先独立取得，再用剩余预算读取预告、分红和股东等资料。辅助请求超时不会清空已取得的财务；估值、核心财务、补值和辅助查询遵守同一总时限。

MX 业务错误不作为正常财务缓存；额度、认证、HTTP 状态及超时等原因由适配器向聚合层传播，单源失败仍与其他源隔离，报告保留固定脱敏原因码。普通 iFinD 补值与交叉验证均保留原因。源接口可能抛出带脱敏原因的 SourceReadError，调用方须在聚合边界隔离，不能把异常文本当数值；资金流入口保持原有空结果降级契约。

Fuyao 补值与交叉验证共用适配器。按[官方接口说明](https://fuyao.aicubes.cn/llms-full.txt)，REST 使用 GET、X-api-key，估值调用 /api/a-share/valuations/snapshot，财务指标调用 /api/a-share/financials/indicators，后者必须提供已确认报告期。abilities 中的指标按官方指标 ID、百分数单位及响应报告期解释；普通净利润同比不能冒充归母净利润同比。利润表 operating_income 与 parent_holder_net_profit 分别采用营业收入、归母净利口径，按响应 period_end_ms（上海时区）、currency 与原币元单位解释；quarterly 未证实累计或单季时保持期间基础未知。无期间时说明 period_unknown，不猜期间。

MX/iFinD 的账户额度恢复、Choice 正式 MCP 地址与权限核对、Fuyao 服务权限由账户维护者处理。连接测试成功不证明额度或数据查询可用。生产数据库迁移仍需独立备份和验收；本修复不自动修改账户或数据库。
