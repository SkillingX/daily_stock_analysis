# A股深度投研报告（Deep Research）

> 本文档描述「深度投研」功能模块的设计、接口、配置与边界。该模块在左侧菜单「首页」下方，提供机构级 A 股深度投研报告的生成、PDF 下载与历史管理。

模型调用的后续优化见[分阶段实施规格](model-workflow-optimization.md)，包括调用归因、技术/资金单轮分析试点、分析成文收敛和有界等待；该规格描述待实施目标，当前运行行为仍以已发布代码为准。

## 1. 功能定位

- **入口**：左侧菜单「深度投研」（路由 `/deep-research`，菜单第二位）。
- **形态**：表单输入 A 股代码/名称 → SSE 流式生成 → 报告展示 + PDF 下载 + 历史列表。
- **分析框架**：五层穿透（宏观定方向 → 产业定赛道 → 财务定质地 → 估值定价格 → 博弈定节奏），每层强制注入「政策敏感度」因子（筹码结构已随 issue #46 退休）。
- **范围**：MVP 仅支持 A 股（沪深京：60/00/30/688/920/430/83 开头 6 位代码）。港股/美股后续扩展。

## 2. 架构

```
DeepResearchPage (表单+SSE+报告)
   │ fetch SSE
   ▼
api/v1/endpoints/deep_research.py (5 接口, /api/v1/deep-research/*)
   │
   ▼
src/services/deep_research_service.py (编排: 校验→生成→存盘→清理)
   │
   ├─ src/agent/deep_research_executor.py (ReAct + 五层穿透prompt + 降级 + 质量重生成)
   │     └─ run_agent_loop (复用) + 10 个问股工具 (精确筛选)
   │     └─ src/agent/deep_research_validator.py (三层防线 L2 检测)
   │
   ├─ src/md2pdf.py (Markdown→HTML→PDF, xhtml2pdf+reportlab CID CJK, 惰性+Semaphore限流)
   │
   └─ src/storage.py: deep_research_reports 表 (SQLite CRUD, 并发安全)
```

与问股/郑希/供应链对话框模式的差异：**表单一次性生成**（非多轮对话），历史通过 `deep_research_reports` 表持久化（非 conversation 表）。

## 3. API 接口

所有接口挂 `/api/v1/deep-research`，继承全局 AuthMiddleware。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/generate/stream` | SSE 流式生成。事件：`thinking`/`tool_start`/`tool_done`/`generating`/`done`/`error`/`heartbeat`（30s 心跳）|
| GET | `/runs/{run_id}` | 当前运行状态：running/cancelling/finishing/finished；进程内查询 |
| POST | `/runs/{run_id}/cancel` | 取消指定运行；等待实际在途清理，重复调用不影响后续运行 |
| GET | `/reports?limit=50&offset=0` | 历史报告列表（分页，按时间倒序）|
| GET | `/reports/{report_id}` | 报告详情（含 Markdown 正文）|
| DELETE | `/reports/{report_id}` | 删除报告（元数据 + .md + .pdf）|
| GET | `/reports/{report_id}/pdf` | PDF 下载（惰性生成，`asyncio.to_thread` + Semaphore 限流）|

**report_id 格式**：`{6位A股代码}_{YYYYMMDDHHmm}`，允许同分钟冲突后缀 `_序号`，白名单 `^\d{6}_\d{12}(_\d+)?$`（防路径穿越）。

## 4. 配置

| 环境变量 | 默认 | 说明 |
|---------|------|------|
| `DEEP_RESEARCH_TIMEOUT_SECONDS` | `2400` | 报告总预算（秒），包含取数、排队、研究与收尾；正有限数。研究为收尾保留最多180秒，到期停止新工作，规则保存有效资料；实际在途资源继续清理，不伪装已结束。|
| `DEEP_RESEARCH_LLM_CONCURRENCY` | `3` | 同一进程所有模块的实际模型请求上限；正整数，空值沿用3，非法值启动失败。流式直到关闭才释放；本机可设1。保存后重启生效。独立CLI、调度、Desktop与其他后端分别计数，不是账号级总额度。|
| `DEEP_RESEARCH_MAX_REPORTS` | `200` | 保留报告数量上限（超出删最旧，含 .md/.pdf 文件；`0` = 不清理）|

**系统依赖**：PDF 生成采用**纯 Python 方案**（`xhtml2pdf` + `reportlab` 内置 CID CJK 字体 `STSong-Light`），`pip install -r requirements.txt` 后即可工作，**无需安装任何系统二进制或字体文件**，macOS / Linux / Docker 全平台一致。渲染失败时优雅降级（返回 404，不影响报告生成）。

> 历史说明：早期版本依赖 `wkhtmltopdf`（经 `imgkit`）。但 `imgkit` 调用的是 `wkhtmltoimage`（主输出图片，不支持 PDF 输出），且 `wkhtmltopdf` 已于 2023 年停止维护、Homebrew 6.0+ 移除了对应 formula，导致 macOS 本地下载 404。已切换为纯 Python 方案。

**nginx（生产）**：SSE 长连接需 `proxy_read_timeout 1200s` + `proxy_buffering off`（与供应链 SSE 一致）。

## 5. 质量保障（三层防线）

深度研报的质量是核心，采用三层防线防止 LLM 跳层/敷衍：

1. **L1 预防**：精确工具集（10 个，去掉 backtest 噪音）+ system prompt 检查点（每层必须调用特定工具）。
2. **L2 检测**：`DeepResearchValidator` 校验五层覆盖（关键词 + 工具调用）、结论前置（≥7）、三情景概率和（≈100%）。
3. **L3 兜底**：校验失败 → 追加提示重生成 1 轮；再失败 → 输出报告 + 顶部标注「⚠️X 层不完整」。步数耗尽 → 从已收集数据生成部分报告（不返回空）。

详见 `data/deep_research/system_prompt.md`（五层穿透框架，可迭代不改代码）。

## 6. 存储与清理

- **元数据**：SQLite 表 `deep_research_reports`（id/stock_code/stock_name/created_at/md_path/pdf_path/status/quality_score/missing_layers/...）。并发安全（`_run_write_transaction` 带锁重试）。
- **正文/PDF**：`reports/deep_research/{report_id}.md` 与 `.pdf`（Docker `/app/reports` volume 持久化）。
- **清理**：生成后若总数 > `DEEP_RESEARCH_MAX_REPORTS`，删最旧（事务内删元数据 + 事务外删文件）。

## 7. 边界与降级

- **数据缺失**：政策评分/行业高频价/龙虎榜等无专门数据源 → LLM 基于公开信息推断，**必须标注「数据缺失/基于推断」**，禁止编造。
- **单数据源失败**：复用 `DataFetcherManager` 多源 fallback，不拖垮报告。
- **超时**：有限报告总预算与各阶段预算共同生效；SSE 30s 心跳；前端90s无事件按连接中断处理，后台任务继续。
- **认证**：单管理员模型（历史报告全局可见，无用户隔离）。

## 8. 排障

| 现象 | 排查 |
|------|------|
| PDF 下载 404 | 检查后端日志 `[md2pdf]` 相关 warning（渲染失败原因）；确认报告正文（.md）非空；纯 Python 渲染无需系统依赖，404 多为正文空或 xhtml2pdf 缺失 |
| 盘中报告「当前价」=昨收 | `analyze_trend` 已在盘中自动合并今日实时行情 bar（日志 `盘中合并今日实时 bar`）；若仍异常，检查 `get_realtime_quote` 数据源是否可用、当日是否交易日 |
| 生成超时 | 检查 LLM 配额/网络；nginx `proxy_read_timeout` 是否 ≥ 1200s |
| 报告标注「不完整」 | 五层穿透某层工具未调用或内容缺失，可重新生成 |
| 非 A 股被拒 | MVP 仅支持 A 股（6 位数字代码）；港股/美股待扩展 |

## 取消终态、资金复用与超时阶段归因（issue #58）

### 取消契约

- 取消形态异常（裸 `asyncio.CancelledError` 或携带它的 `BaseExceptionGroup`）只有在 **ResearchRun 自身状态**（显式 `stop_reason` 或真实预算耗尽）支持下才解释为用户取消/预算耗尽；SDK 真实超时也会以取消形态冒出，不能见 CancelledError 就宣称用户取消。
- 翻译发生在既有边界：共享 MCP 边界（`call_mcp_tool`）与 iFinD 同步包装（`IfindFetcher.query`）依据 run 状态把取消形态异常翻译为 `ResearchStopped`（未发生用户取消/耗尽时保留真实超时或错误语义）；日线包装（`BaseFetcher.get_daily_data`）不再把 `ResearchStopped` 包装为 `DataFetchError`，取消不污染来源失败计数、熔断与 fallback。
- 阶段 0 收尾读取资料 future 时遵守同一契约：worker 取消形态异常不穿透装配，run 已停止时以 `ResearchStopped` 冒出由编排层收敛中断结果；run 未停止的真实中断如实记入 limitations，不伪装成功。
- API 生命周期（`run_sync`）保证已接收任务**恰好交付一个终态**并结束 SSE：用户取消且中断结果可用时走既有 partial 报告路径；中断结果本身无法交付时发一次携带 run 原因的 error 终态；无用户停止的意外取消保留「报告生成失败」真实语义，不冒充取消/预算耗尽。`KeyboardInterrupt`/`SystemExit` 及含其成员的异常组继续传播，不被终态处理器吞掉。同股票门禁只在真实清理（`cleaned`）后释放，浏览器断线继续执行的语义不变。

### 资金资料复用

- 阶段 0 已取得的合格资金块（金额、交易时点、窗口覆盖、来源、单位与字段资格记录）随本次 run 的装配结果保留到 `SharedContext.fundamental["capital_flow"]`；资金研究员优先复用（同一投影函数），**零新增 NETINFLOW 出站**；无合格块或身份/时点不匹配时走既有有界补查与同报告 single_fetch 去重。opt-in 交叉验证对复用块与取数块完全同语义：验证关闭时为空操作（零出站），开启时主块零重取、核验二源按既有语义出站，冲突结论保持不合格。
- 资金块**不写入 24h 财务快照缓存**：跨报告、跨交易日的动态资金不借财务缓存复活，命中财务缓存的新报告仍按自己的有界补查取得资金。部分资料（如 10 日窗口不完整但当日金额有效）保留其有效性并如实携带缺口与拒绝元数据，不放宽完整窗口或资格门槛。

### 超时阶段归因与参数候选

模型尝试账本（`attempt_records.timeout_phase`）区分五个 `timeout_phase` 取值，准入等待单独记状态（`queue_timeout`），不占 `timeout_phase`；各窗口不是六个互不相关的时钟——实际限制时钟按既有最小预算约束取更小者（排队后剩余预算、调用自身预算与配置上限中的生效者），归因不互相冒充：

| 阶段 | 含义 | 配置键 |
|------|------|--------|
| 准入等待 | 排队等并发名额（消耗调用/报告预算，不占响应上限） | （`queue_seconds`，状态 `queue_timeout`） |
| `first_response` | 响应头 + 首 chunk 共用一个窗口，从真正出站起算 | `LLM_STREAM_FIRST_CHUNK_TIMEOUT` |
| `idle_chunk` | 后续 chunk 间空闲 | `LLM_STREAM_IDLE_CHUNK_TIMEOUT` |
| `response_total` | 已获准出站后的整段响应墙钟，且配置的响应上限是实际限制时钟（调用自身预算更小时不冒充此项），新块不重置 | `LLM_STREAM_RESPONSE_TIMEOUT` |
| `call_budget` | 调用自身预算小于响应上限并先到期（调高响应上限无法修复该失败） | 调用方传入的 timeout |
| `report_budget` | 报告总预算耗尽并取消了同一协程（限制时钟是调用/报告预算；取消走取消契约，不冒充超时） | `DEEP_RESEARCH_TIMEOUT_SECONDS` |

参数候选实验（本地确定性对照，一次只变一个变量；**候选值不是生产推荐值，未部署**。复跑方式与逐次证据记录在 issue #58 的施工/验收记录中，仓库内回归为 `tests/test_issue58_timeout_phase.py` 等真实入口测试）：

- 阶段预算 25→40 秒（`FUNDAMENTAL_STAGE_TIMEOUT_SECONDS`）：虚拟时钟回放生产冷启动耗时 + 合成目标价响应，25 秒重现「目标价仅余约 1.6 秒后超时」，40 秒候选可完成。
- 取数预算 10→20 秒（`FUNDAMENTAL_FETCH_TIMEOUT_SECONDS`）：虚拟时钟回放 worker 重启/登录序列（tradedates 约 6.7 秒 + 合成 NETINFLOW 约 6.7 秒），10 秒重现「NETINFLOW 仅余约 3.3 秒后超时」，20 秒候选在同一合成序列内完成。
- 首响应 10→30 秒（`LLM_STREAM_FIRST_CHUNK_TIMEOUT`）：真实 SDK/loopback 对照（同一延迟响应、固定响应墙钟）：首响应窗口不足时失败、放宽后成功；排队中的请求不占首响应窗口，证明提高响应总上限不能替代首响应设置。

以上合成计时均为确定性反例回放，不是供应商实测；更高覆盖与可接受等待的最终取舍以真实对照和 PM 目标为依据，生产修改需单独授权并重启对应进程。

### 部署依赖组合

已验证组合为 `litellm==1.106.4` + `mcp==2.3.0`（`requirements.txt` 明确固定）。普通工具声明即使不含 MCP 工具也会进入 LiteLLM 的懒加载 MCP 导入路径，旧 MCP 1.x 下该路径在请求时因 `CacheableResult` 导入失败，而 `pip check`、健康检查与普通模块导入均不报错；`scripts/check_tool_deps.py` 在部署脚本安装依赖之后、停止旧服务之前检查该真实导入链，失败时保留旧服务继续运行并中止切换。不建设旧 SDK 兼容路径。

## 缺失估值与刷新

情景概率不等于目标价证据。当前情景载荷不包含目标价来源及计算依据，因此保留定性情景，取消现价固定倍数和无来源模型目标价生成的 EV、价值区间与时间目标；仅有 PE/PB 数字也不构成完整估值。相关情景、结论和信号明确降级为观察，独立技术点位仍按已有 ATR/支撑规则提供，不增加新的估值模型。

## 作战计划点位口径与数据限制披露

作战计划的入场、补仓、止损、止盈处于同一计算语境：理想买价取支撑 + 0.5×ATR（不超过现价），补仓价再低 0.5×ATR；**止损相对首批入场锚计算**（MA20 与入场价 − 1.5×ATR 孰近的下沿），不与现价锚混用。四项点位必须满足多头条件买入方案的必要关系（止损 < 补仓 < 首批 ≤ 现价、止盈 > 首批，且均为正的有限数值）；支撑位为脏值（≤0/非有限）或 MA20 紧贴入场锚导致关系不成立时，不输出可执行点位，保留观察并写明触发条件与原因，不以放宽校验或固定倍数凑数。

报告的入场计划与风控文案区分两类读者：未持仓读者的**条件买入计划**（价格回落触发、非按现价追高）与**已有持仓参考边界**（止损锚定首批成本；报告未取得用户持仓成本，不声称为用户实际持仓计算止损）。可执行操作及触发条件只有一个来源——规则作战计划：操作决策表由规则按方案点位与持仓状态直接生成（空仓条件买入行、已持仓止损止盈纪律行或观察行），经理矩阵不采信；经理内容（含标题、小计、情景、核心论点、赚钱路径、风险矩阵、全部节叙事与内容概括）只解释事实，不另发交易动作或风控执行条件。含交易动作词的内容块保守弃用，回退已有规则说明或研究员原文；不判断执行词与价格的距离，也不按数字猜买卖角色。即使经理是在复述正确方案或历史交易，该块也不采用。事实数字（现价、估值、量比、财务阈值）本身不会触发拒绝；含交易语汇的事实解释可能一并回退，但原始研究资料、来源和规则表保留。正文可写「按作战计划触发条件执行」，具体操作统一见规则表。ATR 对平价日线（无波动）或含异常值历史先降级观察，不输出点位方案。

技术面周线过滤按交易日期归并周收盘（每周最后有效收盘，W-FRI 口径），不对多日收盘求和；共享快照不足 200 周样本时按需有界补取一次，仍不足（含上市不足 200 周）则该指标按纪律记缺口并说明真实样本数，不放宽门槛或填充数据。消息面正文按大界保留原文，仅极端超长才截断并披露；事件日历、单事件结果/预案超出条数上限（10/8/8）时，丢弃数量写入报告的「内容限制披露」随保存展示。

### 取消与连接生命周期

提交可传可选 `run_id`（32位小写十六进制），旧客户端不传时由服务端生成。HTTP响应头 `X-Research-Run-Id` 与首个 `accepted` 事件回显该标识。前端提交前生成标识，接收确认前点击取消会等待接收后再发送取消请求。取消停止后续模型/工具工作，已有有效资料可保存为部分报告；没有有效资料时不创建空报告。取消会中断流式模型响应的读取并关闭连接；仍在清理或确不能立即中止的同步工具调用继续占用额度和同股去重直到结束，清理完成才发最终 `done`；期间可先收到 `partial_ready`，不表示后台已停止。

关闭页面、切换路由或SSE断线只断开监听，已接收任务继续执行，生成产物进入原有历史。股票代码统一后去重，取消后的清理期间也不能重复提交同股任务。运行标识区分每次任务，旧取消请求不影响新任务。事件队列最多128条、完成回执最多256条，断线后不积压事件；状态与取消接口继承全局认证，不承诺重启恢复、跨进程协调或事件重放。

### 阅读部分报告

总览的“正常 / 未完整完成 / 主动未选”来自实际章节状态，表示本次研究进度，不是数据准确率、资料覆盖率或股票质量。缺少完整维度状态的历史报告不推算完成数；legacy的 `quality_score` 保留结构校验器评分含义。默认完整范围（issue #64 起为当前 18 项有效维度），自选称“分析范围”；历史报告按其保存产物展示。

部分章节先列有效事实与参考来源，再说明模型响应超时、排队、预算或取消等实际原因；无可用资料时不称“已保留资料”。数据局限按采用结果区分（筹码分析与社区评价已随 issue #46 退休，不再产生估算或缺失文案）；财务指标部分或全部取得而补充查询失败时写明已取得几项、缺哪几项，不把部分来源失败写成全部财务无数据，缓存等实现细节不进入用户可见文案（保留在日志与诊断字段）。未形成评分输入不推断为“尚未接线数据源”，中性分及不纳入有效信号的规则保持不变。财务期间、单位、报表和调整口径不足单独说明，不能直接对比不等于数值错误，单源不等于独立核验。显示精度只用于阅读；原始数值、原因代码、资格和供应商证据仍保留在维度JSON，金融规则与来源优先级不变。没有可靠估值依据时继续限制综合结论，独立技术参考不能替代估值。

## 终稿证据输入与受保护研究（issue #66）

经理终稿三波（标题/概括、主干、维度节）的输入按字段感知投影组织，不再对整个 JSON 取前 5000 字符硬截。历史缺陷：超长业务/新闻参考资料摘录在前部占满截断窗口，资金/技术维度整体未进入出站消息，且截断点产生非法 JSON；旧新闻数字反而保留并与已完成研究矛盾。当前规则：

- 每个待成文维度保留信封（状态/时点）、全部标量字段（含 0/负数/False/None）、叙述与全部可追溯工具事实（来源/时点/单位/资格身份键完整，不做条数或条内剪枝——生产者基数有限且核心保留不依赖键序/条序）；超长字符串限量并显式标注截断。
- 检索参考资料作为支撑摘录单独限量（保留 3 条、摘录正文限量），省略条数如实标注；其余结构化字段保留全部键，仅列表条数限量并按路径标注省略。
- 出站消息由构造保证是完整合法 JSON，不设总长硬切，不设第二压缩档。

技术面与资金面两节为受保护研究：研究员单轮结构化研究完成后，终稿不再要求经理重写这两节——正文直接复用研究员叙述，标题用规则标题，评分表「技术面/资金面」小计取六维框架同维度规则摘要；经理返回的旧段落/旧标题/旧小计（如「缺少最新行情」「缺数据」）不覆盖已完成研究。波 A/波 B 注入已完成研究的有界摘要（含完整身份元组与盘面现价），标题、概括与主干解释引用同一事实；维度状态非 ok（真实缺失/degraded）时不改写成有效结论。该边界不承诺消灭模型任意事实错误——模型级真伪不做普遍断言。

市场取数同一停止/I/O 契约见自选股指南：指数与市场统计取数链（先行源 + 全部候选，含候选内部多次 HTTP）共享任务级截止预算（模块常量 30 秒），经既有 `request_deadline`/请求补丁落实到真正的 HTTP 连接与读取；每个候选前读取所属调度停止 Event，预算耗尽或停止后按既有局部隔离跳过剩余候选并保留已取得结果。TickFlow 走 SDK 自带超时（非 requests 传输，不共享该 deadline）；无法中断的第三方调用如实披露，不宣称任意 SDK 固定秒数退出。
