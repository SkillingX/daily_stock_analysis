## 目标与范围

本部署以原生 Choice QuantAPI 作为 A 股财务主源，停止 MX、iFinD、Choice MCP、Fuyao 的所有运行调用。允许未停用的公开来源补充相同指标，但必须满足报告期、币种、单位和口径要求，并显示真实来源；不把同家族来源算作独立核验。

用一个统一市场准入配置将本部署的个股功能限定为 A 股（沪深京），保留港美股代码供以后启用，不全面删除旧适配器。市场准入与供应商选择是不同维度；市场准入不扩大既有证券品类或专项报告的适用范围。

本批先完成 dev 和本机报告验收。服务器账号密码登录验收、正式套餐、并发会话许可、部署及线上验收另行推进。未来同花顺可作为同级供应商接入；本次只实现 Choice，复用现有适配入口，不预建插件框架、独立数据平台或通用服务。

## 市场范围的实际现状与目标

当前四类专项报告（基本面、财务、板块、深度投研）要求 A 股；通用分析、行情 API、自选股、Bot、CLI 和组合入口仍接受港美股，不是仅保留闲置 provider。离线校验确认 `AAPL`、`00700.HK` 被通用分析请求接受、被深度投研拒绝。共用股票联想也包含港美股。`MARKET_REVIEW_REGION=cn` 只控制大盘复盘，不是全系统市场开关。

目标约束：

- Web 联想、市场选项和新建标的与后端准入一致；后端在排队、取数和模型调用前明确拒绝未开放市场。
- API、直接行情、CLI、Bot、自选股触发、调度及 Agent 工具复用同一准入判断，不能只隐藏页面。
- 已有非开放市场任务在执行前检查并明确跳过/拒绝，不能悄悄继续请求；历史报告和已存组合记录保持可读，不删除数据，也不在只读展示中偷偷触发非开放市场实时取数。
- 境外宏观指数作为 A 股研究背景与境外个股任务区别处理，不能通过全局卸载数据源误伤宏观资料。
- 配置默认兼容行为与本部署的 A 股配置分别说明；不为每个页面、市场和供应商堆叠独立布尔开关。

## 最小实现

```text
统一市场准入 → 现有业务入口
                    ↓
       Choice 适配器：会话、查询、字段转换
                    ↓
现有 manager / 年度财报 / 资金流消费入口
                    ↓
      现有质量模型、报告、API 与下载
```

Choice 适配器按供应商职责收敛；复用现有字段证据、预算、刷新与缓存机制。字段一并查询，不每个字段重新登录；单进程复用会话并串行访问原生 SDK。原生请求超时必须有界，不能只让等待线程超时后继续无限占用 SDK。多进程共享会话服务只在服务器条件实测要求时再设计。

SDK 作为可选运行依赖，普通离线 CI 不要求设备令牌；未配置 Choice 的环境不能因模块导入失败而无法启动。已选择 Choice 但缺 SDK、未授权或额度不足时明确报告原因，并仅按已批准的补充来源策略处理。生产不自动升级原生库、不自动强制登录踢掉其他会话、不自动删除令牌。

## 数据合同

| 数据范围 | 本批目标 | 约束 |
| --- | --- | --- |
| 最新快照 | ROEWA、GPMARGIN、YOYOR、YOYPNI、PETTM、PB(MRQ)、MV | 先查询截止日已披露财期；财务期与行情日分开；归母净利与营业收入口径明确 |
| 年度利润数据 | 营收、营业成本、毛利金额、归母净利润、加权 ROE、毛利率、EPS | 最多四个已披露完整年报；固定合并报表、人民币、调整前口径；毛利金额与百分比不混用 |
| 年度资产与现金流 | 总资产、总负债、归母权益、经营现金流净额 | 对接实际消费层；负债率及现金质量只在所需字段有效时计算 |
| 资金流 | 当日主力净流入及五/十交易日窗口 | 按真实交易日历取序列，日历不可用或窗口不足均不得标记完整；单位未经确认不参与金额计算 |
| 行业/板块及其他研究资料 | 保留未退役来源的现有能力 | 板块成交额与个股主力净流入是不同指标；不因个股资金缺失误判板块全部不可用 |

年报候选已实测字段：`OPERATEREVENEW`、`OPERATEEXPNEW`、`PARENTNETPROFITNEW`、`GROSSMARGIN`、`ROEWA`、`GPMARGIN`、`NETOPERATECASHFLOWNEW`、`SUMASSETNEW`、`SUMLIABNEW`、`SUMPARENTEQUITYNEW`、`BASICEPSNEW`、`ACTUALISSUINGDATE`。资金流候选为 CSD `NETINFLOW`，不可借其他证券类型或 CTR 同名字段的单位来代替本指标定义。

不足四年按实际年数展示；只有一个可比年度不计算年度同比。零值和负值保留，空值不填零。金融行业不适用的科目明确标记，不为本批建设全行业财务模型；财报分析的现有 period 参数不得被当作已经支持季度取数的证据。

来源、财期、披露日、币种、单位和调整口径贯穿实际消费与输出。主源可用不等于已独立核验；不因更换供应商改变既有评分公式。历史报告保留原始来源，新缓存区分来源与合同版本，旧快照不得重标为 Choice。强制刷新必须覆盖新接入的快照和序列，业务失败不能固化为成功缓存。

## 缺失与失败行为

用户已确认：Choice 与允许的补充来源仍无法提供合格数据时，保留已有有效内容，明确报告不完整及原因；依赖缺失或不合格字段的评分、估值、目标价和行动结论不生成。只具备部分财务评分组件时，不能宣传为完整财务健康结论。

复用现有质量与降级语义，不新建第二套状态系统。SDK 缺失、认证失败、权限不足、额度不足、超时、真实空值、字段不适用和口径不匹配必须可区分。真实缺失可以形成诚实的部分报告；代码映射错误、装配断点和单位转换错误不得被包装成“数据源缺失”而通过验收。

## 市场准入运行配置

`ENABLED_MARKETS=cn` 开放沪深京个股。未配置时兼容上游的 `cn,hk,us`，空集合或未知市场在启动时失败。修改后重启 API、CLI/调度进程并重新加载页面；Settings 展示该部署配置，市场选择由 `/api/v1/health` 返回的集合决定。直接 API、队列提交/执行、Bot、CLI、研究工具与组合写入共享判断；组合与历史报告读取仍可用，禁用市场使用数据库已有收盘价，无法定价时显示不可用。境外宏观指数的内部数据通路保留。

## 原生 SDK 的运行准备与失败处理

- 本部署在根 `.env` 使用 `DATA_SOURCE_PROFILE=choice`，不配置时沿用 `legacy`。修改来源策略后重启服务和调度进程。无需普通 `CHOICE_API_KEY`；官方设备令牌只由 SDK 管理。
- 在运行 DSA 的同一个 Python 环境安装官方 SDK、对应平台原生库并按官方安装说明注册 `EmQuantAPI`。例如运行 `python -c 'import EmQuantAPI'` 验证注册；SDK/令牌/激活工具不纳入仓库、镜像或 CI。注册路径应由环境安装管理，不硬编码在业务代码中。Linux/容器推荐账号密码登录，无需设备激活；若选择设备文件登录仍受设备绑定限制。本机成功不证明服务器会话许可或运行可用。
- Choice 七项快照带已披露财报期、披露日、估值交易日以及合并、人民币、调整口径。只代表东方财富单源，不作为独立交叉核验。缺字段、无授权、无额度、登录失败、SDK 不可用和超时继续保留可用部分，规则只消费有效输入。
- 本机无响应代理实验中，SDK `HTTPTimeout=1` 的登录仍超过 12 秒未返回。故仅为原生 SDK 使用一个串行、可终止的子进程：正常复用设备会话，沿报告剩余预算等待，超时终止该进程并释放连接，下次重新建会话。没有 ForceLogin、删令牌或自动升级操作；退出时尝试正常关闭会话。进程回收有最多约 0.4 秒的额外清理预算。
- Choice 策略不装配 MX/iFinD，核验注册不启用四旧源，年度及资金旁路不读旧源缓存或旧密钥。来源合同与映射版本进入缓存身份；历史报告保留原始来源。强制刷新不复用当前财务快照。
- 其他部署仍可使用 `DATA_SOURCE_PROFILE=legacy`；本部署回滚不能自动恢复四退役渠道。旧版本无法维持隔离时暂停受影响的新报告生成、保留历史读取，按上文回滚边界处理。

## 年度财报与财务报告

Choice 取最近最多四份已披露年报（合并、人民币、调整前），保留科目金额、加权 ROE 和披露日。现金流和归母权益分别进入现金流表及资产负债表；毛利金额与营业收入减营业成本核对。已知值为零或负数仍保留，不足两年、相邻年份缺失或前期为零时不计算同比；亏损时不使用现金流/净利比率解释利润质量。金额公式使用 Decimal，加权 ROE 不用期末权益反推。

财务分析页面的“刷新数据并生成新报告”对应 `POST /api/v1/financial-analysis/generate?stock_code=<code>&force_refresh=true`。普通生成仅复用当天相同来源及分析版本的完整报告；缺数、源失败或旧分析版本重新取当前快照和年报，不退回更早的完整报告。Choice 与 legacy 的刷新都绕过年度、快照与报告缓存，保留历史版本。

生成响应增加 `partial`：表示报告已保存但有明确缺口，Web 仍可查看与下载。`success` 表示完整报告；`already_exists` 仅表示复用完整报告；`failed` 仍表示生成或保存失败。持久化 `analysis_json.gaps` 与 `analysis_version` 保留完整性和计算版本，旧报告仍可读，但不会作为新版完整结果复用。PE、PB 统一取自共享快照的合格字段，不使用年度旁路的无质量元数据标量；年报序列的 partial 状态同样进入报告缺口，即使缺项不在最近两年。估值失败原因进入缺口，局部财务评分不产生行动建议。不适用字段不能承诺等待源恢复后补齐。大于 10 的有限现金流/净利比率可能来自低利润基数，不作人为截断。

业绩报告服务目前没有独立 Web/API 页面；可通过 `src.services.earnings_analysis_service.generate_earnings_report` 调用。其 Markdown、三表 CSV 和计算 CSV 保留实际来源，按报告分目录保存；仅支持已取到的年度报告，指定年报时选择该年度及更早年份。

本机验收可重跑：`.venv/bin/python scripts/check_choice_reports.py --base-url <local-api-url> --code 300260 --kind financial-analysis --output-dir .claude/reviews/choice-acceptance`。其他报告类型用 `--kind fundamentals` 或 `sector-analysis`，脚本检查生成、API 重读、下载内容相同，不调用通知入口。英文首页未同步，因为此内容是本部署的中文专题说明，未改变首页级定位。

完整深度投研使用 `--kind deep-research --timeout 1200`，默认全维度并强制刷新；只有显式传入 `--dims fundamental sector capital` 才运行局部测试。此前三维度样本不能代表全量上线验收。完整验收必须检查每个维度的实际状态和缺口、页面及下载格式、关键数据证据和最终结论，不能只凭报告已保存或 HTTP 成功判定可发布。

## 资金流窗口与当前验收边界

资金工具在 Choice 策略下只读原生 CSD `NETINFLOW` 和原生交易日历。五/十日完整性按期望交易日期检查，重复日期不重复计入，缺日、空值、短序列和过期观测均不会冒充完整累计。合法零/负值保留；最近观测日期与期望日期分别返回。原始序列只留在适配层诊断，未经单位确认的值不传给研究模型作为金额。

官方 CSD 个股指标目录虽未明确 NETINFLOW 单位，但已于 2026-10-13 完成同口径公开金额实证（见下节）。当前映射按人民币元输出；日/五日/十日金额分别要求对应窗口完整。收盘前使用上一已收盘交易日，假期由原生交易日历处理；不把盘中部分金额或缺日序列当完整日累计。只有金额可用时才允许资金流评分；机构持仓评分仍需要独立的机构数据依据。

单位无需再等 PM 书面说明。资金查询没有独立成功缓存，报告强制刷新会重新取数；基本面快照仍遵循既有缓存与刷新入口。来源家族为 eastmoney，不把公开同源校准称为独立交叉验证。

审查补齐了技术/供应链工具与预警的市场准入，保留公开预告、分红、机构、龙虎榜和板块能力；供应链财务也使用统一 Choice 字段证据。业绩 Markdown 使用计算 CSV 同一份有效同比，缓存年报完整验证金额及披露日期，财务 PE 采用合格的估值快照。新契约测试已加入 type-safety 工作流；深度投研生成、历史详情和下载使用相同展示归一化。

经理终稿与最终 API 结论遵守同一证据资格：基本面、资金、情景估值、结论或信号不完整时，不采纳没有逐条依据绑定的全局摘要、目标价、赚钱路径或操作矩阵，明确提示依据不足；保留原始研究员的独立维度叙述、结构化证据和原有技术资料；核心依据不完整时跳过全部经理分节标题/叙述改写，避免经理在正常分节内重新引入综合建仓或减仓结论。不靠关键词删除猜测句子是否可信。降级/未选择维度仍不接受经理覆盖节标题与叙述；机构/股东资料没有合格字段证据时只作线索，不把股东户数当持仓方向。

## 深度投研最小补齐与估值参考

Choice 快照补充最新已披露财期的 `SUMASSETNEW/SUMLIABNEW`（合并报表、调整口径、人民币元），资产负债率按同财期负债/资产计算，不用年度值冒充中报。`HISSW2021` 提供截至日期的申万一级行业；未取得时显示行业未知，不以股票名称充当行业。主营业务/产品/简介与实际控制人使用 `MAINBUSINESS/MAINPRODUCT/COMPROFILE/AHOLDER/AHOLDERTYPE`，前十大股东使用已披露报告期的 `HOLDNAMER/HOLDPCTR,Rank=11`；返回比例为前十名合计，不伪造个人比例。公司简介不等同年报原文，未披露订单/客户等仍明确缺口。

估值采用 Choice `RATINGTARGETPRICE/RATINGTARGETPRICEMIN/RATINGTARGETPRICEMAX`，参数 `EndDate` 和 `Cycle=180`。显示“机构目标价综合值/最低/最高”，保留人民币元、截止日期和统计窗口，不假设综合值计算算法。该窗口不是目标价期限，上下限不是置信区间或乐观/悲观情景。新增 `analyst_target` 与 `target_price`；`valuation_basis=analyst_consensus`，原 `expected_value` 保持空值，不能把供应商参考价冒充概率加权 EV。无覆盖、错误、过期或矛盾数值时不生成目标价；真实有值才可供既有规则评估，参考价不高于现价或现价缺失时不得据此建仓/加仓。

实际验证：300260 的180日目标价为空；000001 的当前综合值14.155714元、最低13.21元、最高15.10元，历史截至2026-09-01为14.13元，证明日期参数实际生效。接口成功空值不等于没有权限。进一步的研报覆盖/权限只在明确供应商错误后协调；不需要额外 API Key。

### 账号密码登录及补充接口实测（2026-10-14）

根据用户转达的 Choice 支持答复，服务器尤其 Docker 推荐 `start` 账号密码登录；该方式无需生成绑定设备码的 `userInfo`。原本将服务器设备激活作为必要准备的结论已修正。

- 在本机私有 `.env` 或部署凭据中同时配置 `CHOICE_USERNAME`、`CHOICE_PASSWORD`；环境变量优先。两项均为空时保留本机设备文件登录；只配置一项或含逗号、换行、NUL 时返回 `invalid_configuration`，不回退到旧令牌。官方 Python SDK 的登录字符串以逗号分隔，不能安全表示含逗号的凭据；遇到该情况需供应商提供支持方式，不自行转义或修改密码。
- SDK 子进程内读取凭据，传入官方 `UserName` / `PassWord` 参数；保持 `ForceLogin=0`、`RecordLoginInfo=0`，不输出SDK日志、原始登录报错或登录参数。配置注册表将两项均标记敏感；普通配置查询由服务端遮罩（包括无schema及环境变量来源），保存遮罩值不会覆盖真实凭据。配置查询保留文件中的 `${VAR}` 表达式，不在展示时展开，防止凭据经其他字段间接返回；运行时读取仍沿用原有插值行为。两项仅作为部署配置，不通过网页编辑；受独立权限保护的显式配置备份仍保留原文件内容。修改后重启实际持有 SDK 会话的应用进程；目前不新增热切换或会话代理。
- 官方支持确认一个账号默认仅一个进程登录。本机与线上、API worker与独立调度不得依赖强制登录互踢；需要同时运行时联系客户经理取得多点权限。服务重启恢复、正式权限和Linux实测仍需验收。
